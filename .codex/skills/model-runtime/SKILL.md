# F03 模型基础

先读 [功能说明](../../../docs/features/f03-model-runtime.md)、架构 §13.1/13.5、开发进度与 coding/tdd。沿用已确认的 HTTP、模型任务入口、配置及进程恢复测试边界，无需重复确认。

- `packages/contracts/src/models.ts` 维护跨终端 schema、类型和中文字段注释，数字码仍集中在 api.ts。源代码导入不写 .js，运行脚本指向真实 dist 文件时保留 .js。
- 供应商地址、能力和凭据引用属于部署配置 `.env.models`，不能从用户请求或模型输出取得。公开目录只能显示标识、能力、凭据是否就绪及上限，不导出秘密。普通配置发布和历史回滚不改变部署上限。
- `ModelRuntimeService.execute` 是业务模块统一入口；提示词与本地输出 schema 由该模块拥有，版本必须匹配任务配置。诊断使用独立上下文，不能被当作真实经历。作用范围在派发和返回候选前校验，业务提交仍检查版本、来源和生命周期。
- 外部 adapter 每次只发一个请求，不隐式重试。HTTP 超时涵盖响应正文，限制响应体积且禁止重定向；结构化输出、完成状态、向量维度和用量都视为不可信。
- 用量与配置分别持久保存。调用前用同一部署行锁原子检查全局/任务额度与并发；先检查所有作用域再增加计数。外部访问在事务外；结算回到原日期窗口，不能跨日误扣。
- 真实供应商价格未设置时禁止调用；免费本地服务须明确填零。金额为配置价格估算的整数微美元，不冒充账单。供应商超报时如实记账并阻止继续超支。
- 失败、取消、超时及进程中断保留已占用额度，只有可信用量才能结算。重试按实际尝试分别计数；未知请求和同幂等键不会自动补发。重启、改配置、回滚不能重置计数。
- 取消和过期状态不能被迟到输出改回成功，但可观察用量仍需结算。客户端断开不等于取消。模型调用的过期检查仍由查询/派发触发；F04 worker 会查询自己的持久调用，但尚无供应商账单补查。
- 保持前台容量，总并发和后台并发同时受部署上限限制；模型配置变更后旧调用不继续重试或静默换模型。
- 新能力先补公开行为测试。使用真实隔离 MySQL 和本地供应商 HTTP，故障测试可终止自己的测试子进程；禁止将 fixture 成功描述为真实模型语义效果通过。

迁移只追加新文件，MySQL DDL 失败规则沿用 data-foundation。修改后执行格式/lint/typecheck、相关测试、构建、必要浏览器和 Docker 升级/持久化验收。`verify:f03` 只用测试 adapter，写三条诊断且不修改用户配置；不在用户真实模型配置上强行切换以通过验收。

功能交付更新 README、plan/progress 与本技能，在已授权的 dev 分支追加提交并推送，提供固定 SHA、比较基线、启动验收步骤，停在本次用户授权功能供 review；F04 任务集成维护同时阅读 durable-tasks。

F05 人格整理已通过 execute 接入：persona 的新安装默认定义为 persona-initial-v1、输入/输出上限为 32768/4096；旧 probe-v1 占位仅在显式启用时追加定义绑定，不改模型、价格或限额。维护具体采用规则时阅读 companion-personas 技能；测试 adapter 不具备语义整理能力。

F06 的 executeStreaming 复用同一预留、身份和结算流程，业务输入最多 65536 字符（HTTP 诊断仍为 4000）。流式请求不自动重试；供应商 streaming 默认 false，确定性测试供应商为 true。真实流在收到结束标志后验证完整结果，失败/未知保留已用预算。聊天的片段提交规则见 private-chat；取消与发布必须共用模型锁。新安装 chat 的输入上限为 32768，输出仍为 512；旧占位定义显式绑定不改变原限额。

F07 已接入生命周期限制与清理。涉及消息来源、实例代次、任务恢复、模型候选或人格版本的改动，需同时阅读 [lifecycle](../lifecycle/SKILL.md)，接入读取/派发/提交检查及分批清理协议，保留共享原文和全局计量边界。
