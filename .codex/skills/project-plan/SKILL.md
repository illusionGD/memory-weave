---
name: project-plan
description: >-
  在新项目或重大项目启动阶段，梳理目标、范围、阶段、里程碑、技术准备等前置事项，
  形成可供用户评审的项目计划。适用于项目启动和整体规划，不用于单个功能的工单拆分或直接编码。
---

# 了解项目现状
- 阅读用户需求和仓库上下文
- 确认计算栈，如果用户没提技术栈，后续research时提个技术栈推荐

# 技术调研
- 阅读`research`skill，调研并总结相关文档给用户review
- 根据用户意见修改相关文档，直到用户没问题后进行下一步写计划

# 写计划
- 根据相关文档，指定总体的计划文档-plan.md
- 计划文档列出项目大功能点，并且标上功能优先级，做完后续开发的功能清单，要简洁明了
- 写完plan文档后，给用户review，用户说可以开发才进行下一步开发

# 开发
- 根据plan文档的功能清单开始开发，并写项目进度文档progress.md
- progress.md记录当前开发进度：已完成或未开始功能简略一行描述，当前开发功能记录已完成哪些、剩下哪些、进度卡点等进度
- 开始建立项目，遵循相关项目规范rules
- 每个大功能点流程：`research`调研——`to-tickets`拆分功能——开发——`tdd`验收——写相关功能skill文档，并且实现完后停下来给用户review
