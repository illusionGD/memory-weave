# F09 检索评估基线

日期：2026-10-29。Node 22.23.4 / MySQL 8.4.9 / Qdrant 1.18.3，托管开发环境；不是用户的 2 核 4 GB 服务器。比较基线为 F08 `0d5d4c0`。

## 固定语料与硬边界

[f09-corpus.json](f09-corpus.json) 的三条人工样例和八个查询，通过公开 HTTP 创建原文、采用结构化候选，再核对预先标注的记忆身份。姓名、已有别名、普通陈述、精确对象、故事范围与无匹配属于词法/范围基线；地址变化、旧版本历史、未整理新补充及语义通道由集成场景另测。

验收门槛：基础语料期望证据 Recall@8 = 1；当前事实被旧版本替代、实例/现实故事越界均为零。这里只校验确定性工程行为，fixture 不充当真实 embedding 或聊天语义模型。真实供应商未配置，回答有据程度、复杂同义表达、跨时间指代、成本与人格连续性不填造分数。

运行：配置独占测试 MySQL/Qdrant 后执行 `pnpm --filter @memory-weave/server exec vitest run test/retrieval.test.ts`。测试结束删除本次创建的数据库及该部署身份的向量空间，不写真实伴侣状态。

## 1 万 / 10 万条合成索引实验

复现命令：`node evaluations/retrieval/benchmark-qdrant.mjs`，需要显式 `TEST_QDRANT_URL`、`TEST_QDRANT_API_KEY`。脚本创建独占 collection，finally 删除；种子固定，128 维均匀合成向量，余弦距离，过滤到同 owner、companion、epoch、space 的一半数据。每档 30 次查询，K=8，默认 Qdrant 配置，ANN `hnsw_ef=64`。精确结果作为同一数据集的近邻基准。

| 点数    | 过滤后点数 | 已建 HNSW 向量数 | 写入/建索引及查询总时长 | 精确 P50 / P95   | ANN 请求 P50 / P95 | ANN 对精确 Recall@8 |
| ------- | ---------- | ---------------- | ----------------------- | ---------------- | ------------------ | ------------------- |
| 10,000  | 5,000      | 0                | 0.9 秒                  | 2.08 / 3.57 ms   | 2.18 / 3.78 ms     | 1.000               |
| 100,000 | 50,000     | 100,000          | 29.2 秒                 | 10.74 / 15.89 ms | 3.22 / 5.74 ms     | 0.179               |

1 万档尚未达到默认索引阈值，ANN 请求实际可走全扫描，不能把 1.000 解释为 HNSW 效果。10 万档近似召回明显不达标；高维均匀随机数据本身不代表真实文本向量分布，但已足以说明“总能返回 K 条”不能证明准确。

因此 F09 **默认精确向量查询**，保留 `vectorSearchMode=ann` 作为显式评估选项。启用 ANN 的部署门槛为实际语料 Recall@8 ≥ 0.95，关键地址/权限/故事场景零退步，同时报告延迟改善；不能仅凭候选不足时补扫推断总体召回合格。后续可比较 ef、过滤策略、重排与更大真实数据，不因规模增大自动降低准确性。

以上延迟包含本机 HTTP 往返，不包含 embedding、MySQL、来源 DAG 回查、上下文组装或生成；未测完整部署峰值 RSS、磁盘增长与长期吞吐，不能当作整条 RAG 链路容量承诺。真实模型成本继续由统一调用计量记录，合成实验没有付费模型调用。
