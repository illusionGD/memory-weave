## 1. 交付目标与范围

第一版交付可自行部署的 **后端 API + 独立聊天 Web 与管理后台**，支持电脑和手机浏览器。伴侣的人格、记忆、关系与任务保存在后端，后续 App、桌宠复用协议。

第一版完整范围：

- 多伴侣实例、初始人生与人格锁定、独立记忆和渐进自主成长。

后续范围：原生 App、桌宠客户端、语音、视频内容理解、持续屏幕与游戏感知、跨用户伴侣社交、本地模型训练平台。F03 已提供 OpenAI 兼容适配接口，本地推理可作为独立服务接入，具体能力按服务协议验证。

初期按个人部署、同一用户管理多个伴侣、**2 核 4 GB 服务器、外部模型 API**规划。采用单用户登录与终端凭据，数据保留用户归属字段；多用户注册、组织和计费不在第一版。

## 3. 技术选型与依据

### 3.1 推荐技术栈

2026-10-27 用户选择以 MySQL 替换 PostgreSQL，并确定独立向量库使用 Qdrant。当前 F01/F02 已改用 MySQL 8.4.9、mysql2 3.24.6 和 Qdrant 1.18.3，包含新库结构、Compose、认证健康检查与测试；F09 已实现 Qdrant 业务索引、持久同步任务与检索。用户明确开发阶段无需迁移 PostgreSQL 数据，因此从新的 MySQL 库开始，不开发旧数据导入工具。

| 层次 | 推荐选择 | 用途与取舍 |
| --- | --- | --- |
| 工程 | pnpm workspace + TypeScript | 前后端共仓，统一检查命令；公共契约单独管理 |
| 前端 | Vue 3 + Vite + Vue Router + Pinia | 遵循现有 rules；Pinia 使用 setup store，公共接口访问放 packages/browser-client；UI、路由和状态各项目独立 |
| 界面与图谱 | SCSS + Element Plus；Cytoscape.js | 表单、管理组件按需引入；聊天界面适配移动端；图谱按中心与分页展开 |
| 后端 | Node.js 22 LTS（≥22.20.0）+ NestJS，默认 Express 适配器 | 与用户环境一致；模块化单体，按 M01–M12 职责划分；复用成熟 HTTP 与依赖注入能力 [R1][R2] |
| 主数据库 | MySQL 8.4.9 LTS | 保存原文、实例、人格版本、成长、关系证据与持久任务；是权威数据源；DDL 失败后记录未完成状态并阻止就绪 |
| 向量库 | Qdrant 1.18.3 | 保存可重建的向量与必要过滤字段，支持范围过滤及稠密/稀疏融合；不作为人格与记忆的唯一存储 [R11] |
| 数据访问 | Drizzle ORM + mysql2 + 版本化 SQL migration | 保留领域接口，已替换 PostgreSQL 方言、锁及驱动；MySQL DDL 隐式提交，不能沿用原来的事务回滚假设 [R12][R13] |
| 接口与输入校验 | HTTP JSON / OpenAPI + Zod | 公共 schema 驱动 HTTP 校验、类型及 OpenAPI 映射，S0 验证集成；模型与终端输入同样校验，不另维护重复 DTO 校验规则，不暴露数据库实体 |
| 实时通信 | Web：HTTP 发送、SSE 接收；工具终端：WebSocket | SSE 带事件 ID，重连补读并去重；WS 支持能力、心跳与执行回执；传输回执不代替业务已读 |
| 模型 | 自有任务接口 + 供应商 adapter | 首个 adapter 接部署者配置的生成与 embedding API；另配确定性测试 adapter；不以供应商会话保存唯一状态 |
| 检索 | MySQL 结构化查询 + 词法候选 + Qdrant + RRF | 先建立精确检索基线；中文稀疏编码、ANN、查询改写和重排经评估按需启用 |
| 后台任务 | MySQL job / outbox + 租约、重试、检查点 | 业务状态与索引待办同事务；异步更新 Qdrant，模型调用在事务外。Redis 按缓存、心跳与队列需求引入，持久结果仍回写主库 |
| 文件与部署 | 持久文件目录 + Docker Compose | 一个后端服务、主数据库与按功能接入的 Qdrant；两个 Web 项目独立构建，由服务分别托管；生产 TLS 由部署入口终止 |
| 测试与质量 | Vitest、Vue Test Utils、Playwright、真实 MySQL / Qdrant；ESLint / Prettier / vue-tsc / tsc | 当前验证真实 MySQL 事务与 Qdrant 认证健康；检索阶段增加索引同步与过滤验证；模型效果另做隔离评估 |
| 诊断 | 结构化 JSON 日志、请求/任务/模型调用关联 ID、数据库用量记录 | 首版直接在 M12 查询；不强制另建日志、监控集群 |

S0 固定完整依赖版本、锁文件和容器镜像版本，记录兼容验证结果。上表给出实施基线，已采用与尚未采用的部分分别记录在功能说明中；不使用浮动 `latest` 作为生产升级策略。仓库沿用 Apache-2.0，新增依赖核对许可与第三方声明。

Qdrant 按 owner、伴侣、运行代次、可见范围及有效版本过滤候选，返回后再到 MySQL 校验权限、删除状态和当前版本。向量空间按 embedding 模型、版本、维度和预处理版本隔离，使用独立 collection 或 named vector；换模型重新索引并验证后切换，不覆盖原文与人格成长。图片文件放附件目录或对象存储，元数据进 MySQL，需要时为图片建立独立向量。关系先存主库，Neo4j 等图数据库等多跳查询需求和测量结果明确后再引入。

主库切换覆盖 schema、查询方言、迁移锁与失败阻断、健康检查、Compose、CI 和测试；按用户要求不迁移开发阶段的 PostgreSQL 数据，旧卷与旧 SQL 留档。新建 MySQL 后身份、初始快照、人格版本、来源及成员关联继续按既有领域契约维护；F09 已接入 Qdrant 业务读写。跨库写入通过 outbox、幂等重试、版本和运行代次校验收敛，最近原文与未索引变更仍可直接补入上下文。新的多服务方案需要重新验证 2 核 4 GB 的资源预算。

### 3.2 实现路线对比

以下保留 2026-10-25 的框架路线调研；其中 PostgreSQL 为当时的选择，存储部分现以第 3.1 节为准。能力与许可证为资料事实；开发成本、适配程度为本项目推断；各方案在 2 核 4 GB 下的容量均待测。

| 路线 | 能力、接入与成熟度依据 | 本项目定制与开发体验 | 运维、费用与资源 | 数据边界、迁移与结论 |
| --- | --- | --- | --- | --- |
| **NestJS + PostgreSQL 自建领域模块** | TypeScript 框架，提供模块、HTTP 与测试机制；官方文档完整，MIT [R1] | 人格、共享来源、任务语义自行实现；统一 TS 契约，符合已有前端规则 | 无框架订阅；承担开发、服务器、存储和 API 费用；组件少，容量待测 | 状态与导出格式自主控制，权限由应用实现；**首选**，主要成本在领域正确性 |
| FastAPI + PostgreSQL | Python Web 框架，类型校验与 OpenAPI，MIT [R6] | 同样需实现伴侣语义；增加 Python / TS 双工具链，适合强 Python 算法需求 | 自建部署，无框架订阅；仍需任务和存储运维；未比较性能 | 可自管数据库与 API；当前无 Python 专属硬需求，作为备选，本地推理未来可独立接入 |
| LangGraph 编排 + 自有业务服务 | 开源有状态代理编排框架，MIT [R7] | 可复用执行编排；仍需实现本项目权限、运行代次和共享数据生命周期；需协调检查点与业务事务 | 自托管增加编排学习和一致性成本；托管产品另计，未核价 | 需维护框架状态与业务导出映射；当前流程可显式实现，复杂度增长时局部评估 |
| Letta 自托管 / Cloud | 有状态代理与记忆产品，提供本地服务、SDK 和云入口；参考仓库标注 Apache-2.0 [R8] | 可用于快速体验；本项目锁定成长、删除传播、独立视角等需逐项验证，不能假设开箱即满足 | 自托管需维护其运行时，云服务另有费用和条款；未核报价与目标容量 | 官方当前入口已迁移运行时代码，旧 V1 server 为历史实现；当前运行时许可、完整导出和云数据条款需另核；不作为本项目唯一状态库 |

后端保持模块化单体；独立向量库确定为 Qdrant，Redis 按运行需求分阶段接入，独立图数据库与微服务集群暂缓。

### 3.3 检索、模型与持久化的具体落法

**检索：**先按用户、伴侣、运行代次、成员范围和数据有效性确定可用材料；并行查相关结构化事实、词法候选和向量候选，再做 RRF、去重、来源与版本核对。最近原文、未整理事件及未完成索引的新版本通过直接查询补入，避免新地址被旧记忆遮住。无须用户提出问句才检索。

中文词法检索先验证应用层中文分词、别名与专名匹配，再评估 Qdrant 稀疏向量与稠密向量融合；Qdrant 的稀疏索引不自动解决中文分词和词权重编码。专名和地址保留精确匹配路径，分词器、词表及稀疏编码方式版本化。用固定语料比较关键词、向量、融合与可选重排，未达标再评估专用词法引擎 [R11]。

**模型：**分开配置聊天/工具/视觉、记忆整理、反思与成长、embedding；前三类可以共用模型但分别验证。保存供应商、模型、提示词、schema、预处理和参数版本。持久写入与成长模型升级先跑隔离评估；L1 候选另有追加验证。更换聊天模型保留人格与原有向量；embedding 新旧版本并存、增量同步、成套切换及回退。

**任务：**消息与待处理登记同事务；任务短事务领取后释放锁，以租约和版本控制执行；结果、该实例处理进度与索引待办原子提交。允许外部模型请求重试，保证业务提交幂等；工具结果未知时先核对，不能宣称外部副作用“恰好执行一次”。

**文件与恢复：**文件写完并核验后才发布引用，使用稳定 ID、版本、哈希和清单。导出为带 schema 版本的 JSON / JSONL 与附件包，向量可重建。恢复旧快照前读取最新生命周期记录；记录采用独立于业务快照回滚的持久日志与备份，缺少可确认的最新记录时停止启用受影响旧数据，不能保证未知删除状态下安全恢复。

## 4. 工程结构与必须前置的数据约束

2026-10-30 按用户要求将聊天与后台拆为独立项目。聊天保留私聊、伴侣创建/资料、个人设置与只读记忆；后台承接运行状态、人设/实例管理、整理和清理。两端分别启动、构建和维护视觉风格，共用后端与契约。F10、F15、F21 等后续管理功能加入 `apps/admin`，不混入日常聊天；本次分端不代表这些阶段已经实现。

工程目录按以下结构逐步建立；F01 已创建前后端、公共契约、测试与部署目录，未使用的业务目录按功能需要添加。

```text
apps/
  web/                     # 用户聊天：柔和简洁的陪伴界面
    src/
      assets/styles/       # reset、tokens、theme、utilities
      components/          # 跨页面组件
      views/               # 页面及其私有 components
      router/
      stores/
      composables/
      utils/
      types/
      constants/
  admin/                   # 后台管理：独立 Vite / router / styles / package
    src/                   # 与 web 同样分层，不互相导入 UI 或 stores
  server/
    src/
      modules/             # companions、conversations、runtime、memory 等领域
      infrastructure/      # 数据库、文件、任务执行与外部适配
packages/
  contracts/               # HTTP / 事件 / 终端公共契约
  browser-client/          # 无 Vue 依赖的浏览器 API 客户端
tests/
  integration/
  e2e/
  evaluations/             # 固定语料、期望、模型与检索评估记录
deploy/                    # Compose、部署配置示例
docs/
  architecture.md
  plan.md
  progress.md              # 开始开发时创建
  features/                # 当前功能任务及设计说明
```

后端模块通过各自公共接口写入其拥有的状态，M03 负责协调；M05 的成长候选交 M01 提交。前端 `views` 负责装配、`packages/browser-client` 负责公共 API、`utils` 不依赖业务上层；配置、凭据和数据库实体不得进入前端包。

首轮数据设计就纳入以下约束，后续功能逐步补充表结构：

1. 实例 ID 与 `runtime_epoch` 分开，初始快照和当前人格版本分开；模板不随实例成长改变。
2. 会话和参与者独立建模，共同消息只存一份；成员区间、历史授权、每实例读取/整理范围与补处理区间独立记录。
3. 来源引用可追溯到实际事件或材料版本；发生时间、获知时间、适用时间分开；转述与亲历、虚构与真实分开。
4. 保存、正式发布、实际读取、整理、对用户交付分别记录；草稿与迟到结果不能变成正式经历。
5. 任务携带作用域、输入版本、运行代次及幂等标识；提交和发送前重新检查取消、权限和生命周期。
6. 配置版本与实际用量分别持久化；额度原子预留与结算，重试、取消及用量未知的请求按明确规则计量；重启、回滚配置、重置实例不清零已用总额度。
7. 指定内容删除、重置与删除实例分别建模；共享原文和其他实例有效经历的保留遵循架构第 13.6 节。

### 6.1 每个功能如何远程验收

每个可独立验收的大功能完成后，先交付第 6.2 节约定的代码版本和验收说明，用户可拉取 review，并按文档在本地或自己的云服务器启动。已接通在线验收环境时，同时交付浏览器测试入口。开发方完成技术自验和问题定位，用户评审代码与使用行为，不要求手动操作数据库才能验收。

**在线验收环境：**S0 记录当前云端开发环境是否提供可访问的端口预览，以及访问权限、休眠和链接有效期；若不能稳定访问，可在取得部署连接方式与必要授权后，部署到用户云服务器的独立测试环境。当前尚未配置或部署验收站点，开发环境不是自有长期服务器。在线地址不可用时照常交付可拉取版本与启动说明；临时预览不能当作正式运行地址。

测试部署使用独立数据库、附件目录、账号、测试伴侣和模型预算，不写入真实伴侣的成长记录。若测试与正式服务共用 2 核 4 GB 主机，先测资源余量；压力测试和恢复演练另行隔离，不能同时占满正式服务资源。

每次交付至少包含：

| 交付内容 | 用户可以获得的信息 |
| --- | --- |
| 启动方式；有条件时附在线地址 | 拉取后所需环境、配置示例与启动命令；在线地址注明有效期与休眠限制，凭据不写入公开文档 |
| 固定验收版本 | 构建、数据库迁移与模型配置版本；验收期间保持稳定，更新时明确版本变化 |
| 本次范围 | 已实现功能、暂未实现部分、已知问题；真实模型和测试 adapter 分别标明 |
| 3–5 步验收场景 | 预置伴侣/材料、具体操作与预期结果；可在隔离测试数据上重置并重复验证 |
| 技术验证结果 | 当前功能自动测试、必要的故障恢复验证、失败及限制；不能只给“测试通过”结论 |
| 结果查看入口 | 按功能查看消息、来源、人格版本、任务进度或执行结果；早期 S0 提供基础状态页和验证报告 |
| 问题反馈依据 | 用户提供操作步骤、看到的结果和页面运行编号，开发方关联对应日志并修复 |

例如验收“新地址即时可用”：测试伴侣已有旧地址 → 暂停该测试场景的整理任务 → 发消息更新地址 → 紧接着询问当前地址 → 查看回答及其本轮来源，确认使用刚收到的原文；恢复整理后再次检查结构化记忆和来源。暂停控制仅用于隔离验收环境，不要求用户等待后台周期。

反思、淡忘等定时功能可在测试环境用受控时钟或手动触发任务验证，显示实际采用的测试时间与配置；继续经过正常权限、版本和预算检查。程序约束使用确定性 adapter 验证，语义效果另用真实模型；加速测试不代表已经验证长期人格表现，发布前仍需持续运行观察。

完成技术自验后交付代码与体验验收；问题修复后重跑受影响检查并更新验收版本。`docs/progress.md` 分别记录“已实现并验证、待 review”和“review 通过”，按项目 `project-plan` 的大功能评审流程继续，不把每个内部函数都变成用户验收任务。

### 6.2 每个功能的代码提交与 review

“一个功能”指本计划中可独立验收的功能项，过大的条目在开始前拆成明确的交付范围。开发过程可以小步提交，每次正式交付必须有固定的 commit SHA，用户能够从远程拉取该版本。

1. **持续使用同一开发分支。** 默认在 `dev` 上开发，不按功能新建分支。现有本地文档分支重命名为 `dev`，保留文档基线及已有提交历史；每个功能的提交范围只包含对应代码、测试、迁移、配置示例和文档。只有特殊需求需要隔离改动时才额外开分支，并说明原因。
2. **完成实现与自验。** 按适用 rules 运行格式、lint、类型检查和必要测试，更新功能与进度文档。真实凭据、运行数据、聊天与附件不进入提交。
3. **提交并推送到 origin 的同一分支。** 功能实现和检查完成后，在 `dev` 上追加提交；仅本地 commit 不算可拉取交付。推送后核对远程分支 SHA。若受网络或权限阻塞，说明本地提交号及阻塞原因，不宣称已经可拉取。
4. **交付 review 信息。** 给出 `dev` 分支、比较基线与交付 SHA、远程链接、功能范围、主要变更、检查结果及已知限制，附拉取、配置、启动和验收步骤；数据库迁移说明包含升级与恢复影响。首个功能以文档基线为起点，后续功能以上一个已评审功能的最终提交为起点，提供 `git diff <基线SHA>..<本次SHA>` 的差异范围。验收以固定 SHA 为准，不能仅用会继续前进的分支名标识版本。
5. **处理评审反馈。** 修复以追加 commit 提交到同一分支，重新验证并给出新 SHA 与相对上一版的差异。已交付的历史不擅自 amend、rebase 或强推。
6. **确认后继续下一功能。** 每个可独立验收的功能完成后交付 review，再按用户评审结果和项目既有流程在同一 `dev` 分支推进。保持历史连续，不自动合并或推送到 `main`；特殊分支的合并按明确安排处理。

代码 review 与服务器部署分别进行：用户可以先拉取审查代码，再按同一 SHA 启动验收；已有在线环境时也应显示对应构建版本。文档基线不包含可运行应用，不当作任何业务功能已完成。

当前使用真实测试 MySQL / Qdrant 和临时文件目录；检索阶段增加 Qdrant 的范围过滤、同步与重建测试。外部模型、外部工具、时间和故障点使用可控边界。通过公开查询观察结果，避免测试绕过业务接口读取内部表来证明行为。每次一个失败用例、最小实现、验证，再推进下一行为；不先批量写完所有测试。

每次代码修改执行规则要求的 `pnpm exec prettier --write <changed-files>`、`pnpm lint`、`pnpm typecheck`，以及当前功能的必要测试。合并或阶段交付运行相关集成/E2E 与构建；F01 已提供这些命令。具体结果以对应功能说明和进度记录为准，不将某个功能通过解释为整套系统已完成。

程序正确性与模型效果分别验收：

- **程序约束**使用确定性用例：权限、L0 字段禁止成长写入、候选必须通过追加验证、版本、预算、任务状态、重复提交与删除恢复必须全部通过。
- **模型与 RAG**使用隔离的固定中文语料：姓名/别名、地址变化、时间关系、普通闲聊、无相关记忆、虚构故事、独立观点、旧反思冲突、多伴侣转述，以及“保留直率”等锁定含义是否被 L1 变化间接破坏。预期由场景说明与人工标注给出，不从实现自动生成答案；测试 adapter 通过不代表人格语义效果已验证。
- 记录证据 Recall@K、当前事实命中、过期证据误用、越权候选、回答有据程度、人格连续性、P50/P95、调用与 token 成本。硬边界不交给模型评分；语义评分抽样人工复核。
- S2 建立基线和固定评估集，登记可接受阈值；后续改检索或模型不得只用平均分掩盖关键场景退步。真实调用前配置凭据、价格和金额上限；评估结果不写真实伴侣状态。

## 8. 第一版发布验收

以下清单是发布条件，详细场景继续引用架构第 16 节：

1. 新部署可通过文档启动并登录；电脑、手机浏览器可创建多个伴侣并开始交流。
2. 用户刚改地址，即使提取和索引尚未完成，下一轮也能使用新内容；原文、结构化记忆与向量各司其职。
3. 两个伴侣从同一会话形成独立理解，群聊按顺序接话；邀请、退出和历史开放符合范围，私有数据不被摘要绕过权限传播。
4. 有充分依据时自动反思、形成自传和成长；保留初始人生、锁定与版本，普通闲聊无须硬造目标或人格变化。
5. 图文材料按预算读取；活动有实际进度和成果；终端离线、模型失败、用户取消和服务重启有可解释的恢复结果。
6. 自主活动、互聊和主动联系受统一配置控制；维持架构中后台模型并发 1、互聊每场最多 6 次生成、每次初始 500 输出 token 等默认值，额度按对应作用域累计，不借重启或换任务重置。
7. 重置 A 保留初始快照并阻止旧任务/旧成长回写；B 的有效经历与默认保留的共同聊天仍在；指定内容删除可跨派生数据传播；旧备份恢复先应用最新生命周期记录。
8. 更换聊天模型不丢状态，embedding 切换不混用编码；导入导出和备份恢复保留人格版本、来源、关系及附件。
9. 2 核 4 GB 环境完成持续运行及故障恢复测试；报告并发、数据规模、延迟、内存、磁盘增长、费用与备份恢复耗时，不以空库演示代替容量验证。

频率与预算以架构第 7.4.4、8.5、10.6、10.7 和 13.5 节为业务基准，集中注册默认值、单位、作用域和覆盖限制。计划不另维护一套相互冲突的完整参数表。

## 9. 主要风险与验证安排

| 风险 | 何时验证 | 处理与备选路径 |
| --- | --- | --- |
| 查询层、扩展和运行时版本不兼容 | S0 | 验证向量维度/索引、事务、锁与迁移；必要时局部使用参数化 SQL，保留领域接口 |
| 2 核 4 GB 同时聊天、整理和索引压力大 | S0 基线，S2/S6 扩大 | 后台模型初始并发 1，限制连接池/文件大小/任务批次；测试 1 万、10 万记忆及选择性过滤，达资源上限即记录边界；不承诺固定百万规模 |
| 中文检索遗漏或 ANN 过滤后不足 | S2 | 先精确基线再比较 HNSW；检查权限过滤后的召回和内存；限量迭代扫描、补直接查询，按证据决定是否引入中文扩展 [R4] |
| 不同模型结构化、流式、工具和视觉行为不一致 | S0 adapter，S4/S6 评估 | 能力声明与契约测试；缺失能力明确降级；持久写入模型只切经验证版本，禁止静默换不兼容模型 |
| 重试、退出、重置与删除期间出现迟到结果 | S1 起持续 | 在领取后、调用后、提交前后注入故障；每次发布/提交校验代次、版本、成员和取消状态 |
| 旧备份携带已删除内容，最新日志随机器丢失 | S0 定恢复协议，S6 演练 | 生命周期日志与业务快照独立恢复/备份；报告恢复点和日志水位，无法确认最新状态时阻止启用受影响数据 |
| 外部材料访问与内容进入模型 | S3 | URL 获取限制协议、重定向与目标地址，阻止读取服务器内部地址；限制体积/超时；外部文本不扩展权限，展示内容过滤脚本 |

尚需通过实现验证的事项是版本组合、中文分词器、检索阈值、模型供应商效果、单次上下文预算及实际容量。默认按本计划推进实验并记录结果；这些不再作为逐个产品确认的问题。具体供应商凭据和费用上限由部署配置提供，未配置时仍可用测试 adapter 完成工程与行为验证。

## 10. 调研来源

R1–R10 于 2026-10-25 查阅，R11–R13 于 2026-10-27 补充；选型调研未进行候选产品性能对比或核定云服务价格。精确版本与供应商条款在采用时再次核对。

- **[R1]** [NestJS 文档](https://docs.nestjs.com/)、[模块机制](https://docs.nestjs.com/modules)、[源码与许可证](https://github.com/nestjs/nest)：支持 TypeScript 和模块化服务；用于框架能力依据。
- **[R2]** [Node.js 发布与支持状态](https://nodejs.org/en/about/previous-releases)：按用户现有环境采用仍受支持的 22 LTS；结合当前锁定工具链，将最低支持版本设为 22.20.0，具体推荐补丁版本见 `.nvmrc`。
- **[R3]** [PostgreSQL SELECT / SKIP LOCKED](https://www.postgresql.org/docs/current/sql-select.html)：官方说明适用于队列表的并发消费者；任务租约、幂等和恢复仍需应用实现。
- **[R4]** [pgvector](https://github.com/pgvector/pgvector)：精确/近似检索、过滤及 0.8 起的迭代扫描；说明 ANN 过滤可能导致返回数量不足。
- **[R5]** [Drizzle pgvector 指南](https://orm.drizzle.team/docs/guides/vector-similarity-search)：向量查询与自定义扩展迁移；不等于本项目依赖组合已测。
- **[R6]** [FastAPI 官方文档](https://fastapi.tiangolo.com/)、[源码与许可证](https://github.com/fastapi/fastapi)：候选 Web 框架能力与许可依据。
- **[R7]** [LangGraph](https://github.com/langchain-ai/langgraph)：有状态代理编排框架及 MIT 许可；本次未验证其检查点与本项目事务的集成。
- **[R8]** [Letta 官方入口仓库](https://github.com/letta-ai/letta)：产品入口、当前运行时迁移与旧实现归档说明；当前运行时和云服务另行核验。
- **[R9]** [PostgreSQL 全文检索](https://www.postgresql.org/docs/current/textsearch-controls.html)：分词、词素和排序基础；中文方案仍需专项评估。
- **[R10]** [Element Plus](https://element-plus.org/en-US/guide/design.html)、[Cytoscape.js](https://js.cytoscape.org/)：管理组件与关系图可视化候选；移动端布局和图谱规模由项目验证。
- **[R11]** [Qdrant 过滤](https://qdrant.tech/documentation/search/filtering/)、[混合查询](https://qdrant.tech/documentation/search/hybrid-queries/)、[向量与 named vectors](https://qdrant.tech/documentation/manage-data/vectors/)：范围过滤、稠密/稀疏融合及多向量能力；不替代应用的权限和版本校验。
- **[R12]** [Drizzle MySQL](https://orm.drizzle.team/docs/mysql/get-started-mysql)：mysql2 接入方式，现有 PostgreSQL 方言与迁移需改造和验证。
- **[R13]** [MySQL 8.4 隐式提交](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)：DDL 与事务边界，迁移失败恢复不能照搬 PostgreSQL。
