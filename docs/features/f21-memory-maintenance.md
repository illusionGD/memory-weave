# F21 记忆维护与向量切换

## 记忆维护

`MEMORY_MAINTENANCE_CONFIG_JSON` 集中管理维护开关、每轮间隔、候选批次、时间加分半衰期、压缩与归档候选时间。默认每 24 小时检查至多 12 条普通旧经历，时间加分每 30 天减半，约 30 天进入压缩候选，约 90 天进入归档候选。维护游标持久化。参与正在进行的活动或当前成长依据的经历、稳定事实、偏好、约定和短时状态分别遵守现有规则。

首版压缩在单条已整理的完整经历内折叠逐字重复的整句，能够安全缩短时才保存摘要。原文、对象、时间、当前语义版本和全部确切来源仍可回查。新的实际证据恢复当前层级，被召回本身不会刷新时钟。普通检索略微偏向近期经历，归档条目仍可通过词法、直接定位和显式历史查询取得；仅向量命中的归档细节进入显式历史查询。生命周期操作联动清理摘要。

`GET /api/companions/:id/memories/:memoryId/maintenance?runtimeEpoch=1` 返回当前归档层级、可用摘要、实际证据和采用配置；无已提交维护结果时返回空。

## 向量配置

1. 通过现有配置入口发布新的 embedding 配置。`GET /api/retrieval/embedding-spaces` 查看当前、候选、可回滚空间，以及主库应索引、已索引和待清理版本数。
2. 后台从已保存的权威正文构建候选空间，同时维护当前和上一个使用空间。新的正文、修订和删除经同样的持久流程同步。
3. 用固定样本核对效果后，向 `POST /api/retrieval/embedding-spaces/switch` 传 `requestId`、`expectedVersion`、`targetSpace`、`evaluationNote`。服务检查 Qdrant 的全部确切版本和总数，再核对主库变化并原子选择查询编码与集合。覆盖不足时返回 409，原查询空间继续服务。第一次设立真实空间无需手动切换。
4. 回滚使用同一接口和当前版本号，目标是先前的空间。回滚也验证数据覆盖和删除。模型提供商需继续保留先前编码的连接和授权。部署关闭 embedding 时语义查询和构建一起暂停。

## 验证

先执行 `pnpm db:migrate` 应用 `0011_memory_maintenance`，配置隔离的 MySQL、Redis、Qdrant 后运行 `pnpm verify:f21`。验收使用真实 Qdrant 和本地编码协议 fixture，以 4、6 维区分两套请求，检查构建期间、新版本切换后及删除回滚后的实际结果。长期记忆效果和真实模型编码质量由 F24 评估。
