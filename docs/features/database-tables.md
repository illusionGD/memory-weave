# 业务表盘点与合并验证

2026-11-05：原有 42 张业务表，合并消息片段后为 41 张；不含迁移历史表。

## 逐表结论

所有保留表都有当前业务用途；单靠表名相似或字段少不能判断其冗余。下表列出用途与本轮结论，复杂查询通过 Repository 集中维护。

| 表                             | 用途                                                                           | 本轮结论                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `model_configuration_heads`    | 模型配置的当前指针；行锁同时串行化配置切换与预算预留。                         | 保留独立锁点，避免与 owner 资料或另一种调度互相争锁                                    |
| `model_configuration_versions` | 配置只追加不可变版本；回滚也创建新版本，不覆盖历史。                           | 保留                                                                                   |
| `model_calls`                  | 逻辑模型调用，保存已校验结果与诊断，不保存原始输入或外部错误。                 | 保留                                                                                   |
| `model_attempts`               | 每次实际请求的预留与结算；超时、取消和失败不删除计量。                         | 保留                                                                                   |
| `model_usage_windows`          | 固定 UTC 日统计，global 与任务分别累计；不会随配置版本重建。                   | 保留                                                                                   |
| `owners`                       | 当前部署唯一的管理者；迁移生成身份，请求不能指定部署身份。                     | 保留                                                                                   |
| `companions`                   | 稳定实例及其当前运行代次；共同会话原文不级联归属于实例。                       | 保留                                                                                   |
| `persona_versions`             | 人格版本与初始快照分别保存，版本只能属于对应实例及管理者。                     | 保留修订历史；不是旧程序兼容表                                                         |
| `persona_templates`            | 模板身份与当前版本指针，不存放实例成长或私密经历。                             | 保留                                                                                   |
| `persona_template_versions`    | 模板只追加版本；伴侣创建时固定确切版本及内容。                                 | 保留修订历史；不是旧程序兼容表                                                         |
| `persona_foundations`          | 初始整理的固定来源和首个采用版本，不随着当前人格更新。                         | 保留                                                                                   |
| `conversations`                | 会话保存共享顺序；发布命令在事务中锁定该行后分配序号。                         | 保留                                                                                   |
| `conversation_members`         | 成员身份绑定加入时的实例代次，与历史授权独立。                                 | 保留                                                                                   |
| `visibility_grants`            | 序号授权表达成员期间与历史权限，避免将身份等同于全部历史可见。                 | 保留                                                                                   |
| `messages`                     | 原文单份保存；草稿保存、发布、实际取得和后续整理分别记录。                     | 并入 chat_segments 的轮次与片段位置；新增成对非空检查、同 owner/会话外键及位置唯一约束 |
| `message_sources`              | 引用保留稳定原文和版本；服务层额外校验发言者的会话可见范围。                   | 保留                                                                                   |
| `read_receipts`                | 每个实例实际取得的正文范围；查询与发布不会写入此表。                           | 保留                                                                                   |
| `processing_ranges`            | 每份原文独立登记待整理区间，不能由最大游标跳过未处理空洞。                     | 保留                                                                                   |
| `receive_batches`              | 接收命令的稳定结果，重试复用确切消息集合和首次取得时间。                       | 保留                                                                                   |
| `tasks`                        | 恢复权威记录；任务输入与进度保存在主库，领取不依赖进程内队列。                 | 保留                                                                                   |
| `task_configuration_versions`  | 只追加的调度配置，使用 owner 行锁发布并选择最大版本。                          | 保留                                                                                   |
| `task_attempts`                | 每次领取都保留配置、截止时间和原因；检查点不覆盖旧尝试的诊断。                 | 保留                                                                                   |
| `task_scheduler_heads`         | 独立调度锁行，避免以 owner 外键行排他锁阻塞消息发布。                          | 保留独立锁点，避免与 owner 资料或另一种调度互相争锁                                    |
| `task_outbox`                  | 原文发布和待办在同一事务保存，转交任务也与完成标记同事务。                     | 保留                                                                                   |
| `chat_threads`                 | 用户与单个伴侣的聊天运行指针；原文仍保存在 conversations/messages。            | 保留；合成实验未显示稳定查询收益，也避免扩大会话行的写入范围                           |
| `chat_runs`                    | 一条输入对应的持久回复轮次；模型、任务与原文各自保留稳定身份。                 | 保留                                                                                   |
| `chat_deliveries`              | 显式的终端送达回执，不与伴侣取得正文或记忆处理状态混用。                       | 保留                                                                                   |
| `lifecycle_operations`         | 最小生命周期日志与业务正文分离，完成清理后仍保留限制依据。                     | 保留                                                                                   |
| `lifecycle_message_targets`    | 删除传播只记录原文身份；正文始终只在原文表中保存。                             | 保留                                                                                   |
| `chat_run_sources`             | 已发布回复的来源图只保存精确原文身份，实例清理不能抹掉共同原文的删除传播路径。 | 保留                                                                                   |
| `memory_batches`               | 固定的记忆批次；任务与逐条进度同事务登记和提交。                               | 保留                                                                                   |
| `memory_entries`               | 稳定记忆头，当前失效时不能自动回退旧事实。                                     | 保留                                                                                   |
| `memory_versions`              | 只追加语义版本；显式清理会抹除正文而保留无内容身份。                           | 保留修订历史；不是旧程序兼容表                                                         |
| `memory_evidence`              | 精确证据及保守上下文依赖，不拷贝原文；清理可沿消息 ID 失效版本。               | 保留                                                                                   |
| `memory_dependencies`          | 版本之间的有向依赖，只引用已存在的旧版本，避免复制全部祖先来源。               | 保留                                                                                   |
| `memory_search_documents`      | 可重建词法文档，同时作为向量索引的持久待办；正文只保存在版本表。               | 保留                                                                                   |
| `memory_search_terms`          | 词法倒排只保留派生词项，来源失效时随正文清除。                                 | 保留                                                                                   |
| `memory_vector_indexes`        | 同一正文在不同编码空间分别登记，派发身份及结果进度重启后保留。                 | 保留                                                                                   |
| `chat_memory_sources`          | 记忆参与回复的版本来源图；清掉上下文正文后仍能传播后续来源删除。               | 保留                                                                                   |
| `memory_original_sources`      | 不含正文和引文的来源身份图，重置后仍能追溯已发布回复依赖。                     | 保留                                                                                   |
| `lifecycle_memory_targets`     | 单次删除传播的记忆目标，不能把此前其他原因失效的版本误认为本次目标。           | 保留                                                                                   |
| `chat_segments`（已删除）      | 一条消息至多一条轮次/位置扩展                                                  | 合入 messages，取消列表补查和单独片段写入                                              |

## 合成布局实验

脚本：`scripts/benchmark-database-layout.mjs`。需要显式设置 `TEST_DATABASE_URL`，只创建并删除自己随机命名的测试库。运行：`node scripts/benchmark-database-layout.mjs`。

这是针对相关字段和索引的合成布局对比，不是完整业务压测。与其他回归测试共用同一测试容器，微秒级差异可能包含资源竞争；不把这些延迟换算成产品吞吐承诺。每组 5 次预热、30 次采样，原始查询计划见 [实验结果](../../evaluations/database/layout-results.json)。

| 消息数 | 项目           | 分表中位数 / P95（ms） | 合并中位数 / P95（ms） |
| ------ | -------------- | ---------------------- | ---------------------- |
| 10000  | 消息查询       | 0.437 / 0.617          | 0.351 / 0.558          |
| 10000  | 会话列表       | 0.261 / 0.407          | 0.249 / 0.655          |
| 10000  | 消息与片段写入 | 0.986 / 2.571          | 0.758 / 1.533          |
| 100000 | 消息查询       | 0.473 / 0.56           | 0.383 / 0.454          |
| 100000 | 会话列表       | 0.332 / 0.566          | 0.405 / 0.458          |
| 100000 | 消息与片段写入 | 0.873 / 1.495          | 0.531 / 0.73           |

消息合并减少一次片段表补查；写入时轮次/位置随原文一起插入，省去单独片段 INSERT。已发布内容读取直接按消息的轮次索引，来源删除传播少一次关联。原文的发布事务、行锁、序号分配和终端回执语义保留；草稿不进入已发布片段查询。

会话合并在十万消息样本下中位数反而升高，尚无稳定收益，因此本轮保留 chat_threads。未对该候选实施真实结构变更，也未声称完成其锁竞争压测。

本轮没有合并任务/尝试、人格/历史、记忆/修订、词项/向量空间或多种回执。这些关系是一对多或生命周期不同，合为 JSON/通用 type-id 表会改变索引、约束和恢复规则。
