# 简洁星空聊天与自定义伴侣头像

聊天端采用已确认的深蓝星空与扁平设计：背景采用清晰月牙、疏密星群与蓝紫色柔光，侧栏、气泡与按钮使用纯色，手机聊天页收起侧栏。管理后台继续使用独立的管理界面。

背景在登录页与聊天页面共用，使用本地静态 SVG 和 CSS；月牙在聊天页顶部预留位置，避免与消息文字重叠。装饰层不响应鼠标或触摸、不进入辅助阅读顺序。

## 使用与验收

1. 进入聊天端「伴侣 → 查看伴侣」，在「伴侣头像」选择 JPG、PNG 或 WebP 图片。选图只生成本地预览，点击「保存头像」后才上传；可取消。
2. 图片最大 **2 MiB**、解码最多 **16,777,216 像素**，不接受动画。保存时按方向信息旋转、居中裁切为 512×512 WebP，并去除原图附带的 EXIF 等元数据。当前不提供手动裁切位置。
3. 伴侣列表、资料页、对话入口、聊天标题及伴侣消息统一展示头像；没有上传或图片读取失败时显示默认月亮。
4. 管理后台的伴侣详情也可更换、恢复默认头像。正在打开的聊天通过既有 SSE 更新头像，保留输入草稿和消息内容。其他列表在重新进入或侧栏重新获得窗口焦点时回查。
5. 重置伴侣保留头像；删除伴侣立即禁止读取头像，持久清理任务删除该实例的图片目录后才完成。换图和恢复默认均使旧 URL 立即失效，旧文件由有界巡检回收。

两端同步升级；Windows / Node 22 用户拉取后先停止 dev：

```powershell
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

## 公共接口

| 接口                                      | 输入及行为                                                                                     |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `PUT /api/companions/:id/avatar`          | 原始图片正文，Content-Type 为图片类型；查询参数 `requestId`、`runtimeEpoch`、`expectedVersion` |
| `DELETE /api/companions/:id/avatar`       | JSON 正文含同一组命令元数据，恢复默认头像                                                      |
| `GET /api/companions/:id/avatar/:assetId` | 需登录的二进制 WebP，`Cache-Control: private, no-store`；错误仍走统一 JSON 协议                |

上传/恢复默认的 `data` 是 `{ avatar, avatarVersion }`。`avatar` 包含不可变图片 ID、同源 URL、尺寸、格式、字节数与更新时间；null 表示默认头像。详情返回同一组字段，Chat 新增 `companionName` 与 `avatar`，旧客户端可忽略这些新增字段。

`avatarVersion` 与实例、人格、聊天内容版本分别维护，不会触发聊天清理或模型调用。上传重试使用相同命令、图片和预期版本；当前结果仍匹配时重放。并发旧版本返回 409，不自动覆盖；实例重置后旧代次上传也不能生效。恢复默认在已经没有自定义头像时可安全重放。新图片 ID 由服务端产生，复用旧命令键也不会使旧 URL 重新指向新图片。

## 存储与恢复

MySQL 的 `companions.avatar` 仅保存内部文件引用、散列及命令身份，`avatar_version` 保存并发版本；图片保存在 `DATA_DIR/avatars/<owner>/<companion>/`。不进入初始人生、人格版本、原文、记忆或模型上下文。没有独立公开静态目录，所有读取均检查登录、归属、当前引用和删除状态。

Sharp 解码在数据库事务之外执行，每进程同时处理最多两张图片。完成后再锁实例并复查代次、清理限制和头像版本，将规范化小文件写入并同步，再提交数据库引用。无法确认提交结果时不盲目删除文件；每五秒扫描最多 20 个实例，每实例最多检查 32 个文件，持同一实例锁回收未引用文件，启动后自动继续。数据库记录是引用事实源，不依赖进程内待删除队列。

生命周期新增 v4，末尾追加 `avatar_files` 阶段；保留 v1/v2/v3 的原阶段解释。删除文件在事务外执行，操作已持久禁止该实例新上传；文件删除可重复，检查执行租约与阶段后再提交清理进度。旧协议在途实例不能上传新头像，因此无须更改旧检查点。

备份需同时保留 MySQL 和 DATA_DIR；Qdrant 不保存头像。当前仍是单后端部署，多副本必须共享同一文件存储；对象存储与历史备份导入不在本轮范围。
