# F01 工程基础

状态：实现与验证完成，待 review。比较基线：`d73ece9`；交付 SHA 见 Git 提交记录与本次交付说明。

## 功能范围

建立 pnpm workspace：`apps/web` 为 Vue 3 页面，`apps/server` 为 NestJS 服务，`packages/contracts` 保存公共 Zod schema 与类型。后端在构建模式提供 Web 静态资源；开发模式使用 Vite `/api` 代理。

本功能交付登录、会话恢复、退出、运行检查、默认 API 认证、数据库/文件 readiness、Compose 和 CI。没有实现伴侣或记忆数据，也没有发起真实模型调用。

## 主要选择

沿用总体计划的 TypeScript / NestJS / Vue / PostgreSQL 路线。F01 只需要基础数据库连接与扩展检查，使用 `pg`；Drizzle 与领域迁移在 F02 实现。UI 仅有登录和运行检查，基础样式使用 SCSS，不提前安装图谱和大型管理界面依赖。

Node 22 与 pnpm 11 的具体补丁版本记录在工程配置中；Node 最低为 22.20.0，推荐 22.23.4，类型声明同步使用 22.x。CI 覆盖最低版本与推荐版本，Docker 使用推荐版本；依赖通过 `pnpm-lock.yaml` 固定。workspace 注入依赖在 build 后同步，以支持生产打包沿用锁文件。Docker 将构建产物与生产依赖放入运行镜像，以非 root 用户执行。

F01 为单服务内存会话：登录密码经 scrypt 比较，登录后发放随机 Cookie，会话在服务端校验和撤销，最多保留 10 个、有效期 12 小时。后端重启时会话失效，页面需要重新登录；这不是业务状态或后台任务的持久化机制。登录按直接连接来源限制为每分钟 5 次，暂不信任反向代理提供的来源 IP。

## 公共 HTTP 接口

| 接口                     | 访问条件             | 作用                                                |
| ------------------------ | -------------------- | --------------------------------------------------- |
| `GET /api/health/live`   | 公开                 | 进程存活检查，不展示配置                            |
| `GET /api/health/ready`  | 公开                 | 数据库、vector 扩展和文件目录可用性；不可用返回 503 |
| `POST /api/auth/login`   | 公开，校验来源并限速 | 接收 `{ password }`，建立 Cookie 会话               |
| `GET /api/auth/session`  | 登录                 | 检查会话，无效返回 401                              |
| `POST /api/auth/logout`  | 登录，校验来源       | 服务端撤销会话并清理 Cookie                         |
| `GET /api/system/status` | 登录                 | 查询运行状态，隐藏凭据和连接串                      |

公共类型由 contracts 导出。认证在全局 API 守卫执行，后续接口必须明确声明公开例外；前端路由判断只负责体验，不代替后端控制。

## 拉取后验收

先按 [README](../../README.md) 启动，使用生成在 `.env` 中的 `ADMIN_PASSWORD`。

1. 打开页面，直接访问首页应进入登录页；未登录请求 `/api/system/status` 应返回 401。
2. 输入错误密码，应显示错误；输入配置的正确密码，应进入“运行状态”。
3. 检查数据库和文件目录实际状态，刷新页面后会话仍然有效。
4. 点击“退出登录”，应回到登录页；再次访问受保护接口应返回 401。
5. 用手机宽度访问，表单、状态和操作可正常使用；重启后端后，再访问需要重新登录。

数据库异常时健康检查和页面应反映真实结果，不伪装为“运行正常”。线上部署入口尚未配置，当前交付以可拉取代码和启动步骤为准。

### Node 22 兼容性修正

按用户现有环境，将运行时从 Node 24 调整为 Node 22。本次修正比较基线为 `8dbe881`。最低支持 22.20.0，推荐 22.23.4；下限覆盖当前锁文件中的工具链要求，包括 Rollup 的可选 Linux x64 压缩依赖。Node 类型由 workspace catalog 统一，并通过 overrides 约束传递依赖，避免重新带入 Node 24 类型。
