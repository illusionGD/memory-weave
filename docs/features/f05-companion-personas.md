# F05 伴侣创建、初始人生与人格版本

比较基线：`fdfb54d`。普通创建只需一段人设，后台自动整理，不要求逐字段确认。已提供多个伴侣、初始/当前人格、明确约束管理、模板及历史版本页面。聊天按 F06、自动成长按 F16 实现。

## 升级和验收

停止旧应用，在项目根目录执行：

```powershell
git pull --ff-only origin dev
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

MySQL、Qdrant 继续使用现有服务，不需要 Redis 或新容器。访问 `http://localhost:5173`，登录后进入“伴侣”。

1. 填写一段人设，名字可选。原稿先保存，后台整理状态进入详情；刷新或离开不取消任务。
2. 查看当前人格、固定的初始人格和最初原稿；按版本号回查历史。相同人设创建的不同伴侣拥有独立身份和版本。
3. 可选的“管理长期约束”会追加当前版本，不改变初始人格和原稿；这不是日常自动成长的人工审批。
4. 新建模板、编辑为第 2 版，再查询第 1 版并用它创建伴侣。所选版本固定，后续模板更新不会覆盖实例。
5. 旧 F02 原稿不在升级时自动调用模型。进入详情主动选择“开始整理初始人格”；完成后不能反复重新生成初始人生。

默认 test adapter 只返回固定测试名字和空分类，保留直接指定的明确约束，页面显示测试模式。它验证调用、存储、隔离和恢复，不代表真实语义整理效果。完整原稿始终可见。

另开项目终端：

```powershell
pnpm verify:f05
```

脚本检查 14 项公开行为，保存三位带“F05 验收”名称的伴侣和一个模板，产生三次 test 模型调用。不删除已有数据，只允许 persona 使用 test 且调度启用，不会切换供应商或调用付费模型。运行期间避免其他调用影响用量增量断言。失败后可按输出的任务 ID 查询，不自动重新发送未知调用。

Docker 整套部署：

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build --wait
$env:VERIFY_BASE_URL = 'http://localhost:8080'
pnpm verify:f05
Remove-Item Env:VERIFY_BASE_URL
```

## 数据与边界

| 数据              | 含义                                                                         |
| ----------------- | ---------------------------------------------------------------------------- |
| `initialSnapshot` | 完整原稿和初始设定来源，始终保留，不被模型结果替换                           |
| 人格第 1 版       | F02 兼容的原稿记录，`document=null`、`origin=initial_text`                   |
| 首次整理的人格    | 成功后追加第 2 版；`persona_foundations.initialPersonaVersionId` 固定引用    |
| 当前人格          | `companions.currentPersonaVersionId` 引用当前记录；修订追加版本，不更新旧行  |
| 人格文档          | 名称、身份/背景、可成长倾向、知识/技能状态、明确约束，以自然语言表达         |
| 模板版本          | 仅原稿与直接指定的约束；不含私聊、关系、记忆或当前成长；创建时固定并独立复制 |

`PersonaVersion.profileText` 是来源原稿；整理后的当前人格读取 `document`。后续组装上下文不能把原稿每句都重新当成永久有效的当前倾向。成长将使用独立版本和证据来源。

核心身份、角色与背景作为长期基线。普通“慢热”、兴趣或表达习惯属于可成长倾向。“不懂游戏”进入知识状态，不等于“不喜欢游戏”。明确要求“始终保留独立思考”的原句进入约束；不要求每句话都机械表现某种特征。

分类条目带原稿连续引文，采用前验证确实存在；自动提取的约束直接保留引文，用户单独指定的约束完整保存。模型不得决定 owner、实例 ID、代次、版本或权限。原稿按资料处理，不是系统指令；初始设定也不是实际亲历。

这些检查能拒绝结构错误和伪造引文，不能保证语义分类必然准确。实际模型需要评估身份背景、普通倾向、明确约束、知识与喜恶的区分，以及原稿中的元指令。固定 adapter 和本地 HTTP 夹具不替代语义评估。

## 模型配置和恢复

使用 F03 的 `persona` 用途、`structured` 操作和交互容量，受模型配置、预算、并发和部署硬上限约束。定义为 `persona-initial-v1` / `persona-initial-v1` / `utf8-v1`，提示词与 schema 在服务端维护。

新安装输入预留上限为 32768、输出上限为 4096。输入预留沿用 F03 的保守 UTF-8 字节估算，包括系统提示和 JSON schema，不等于供应商 tokenizer。真实或本地供应商需声明 `structured` 能力，配置实际模型名和价格，免费本地模型显式填零。使用方式见 [F03 说明](f03-model-runtime.md)。

F04 已保存的 persona 默认定义是 `probe-v1`。只有显式创建/整理时，才为这一确切占位组合追加配置版本，保留模型、供应商、价格、限额及历史；自定义定义不会被覆盖。旧的 8192/512 上限也不会自动提高，较长原稿或真实输出可能需要部署者评估后调整。已完成的初始人格不会因为配置变化而重新生成。

创建事务同时保存原稿实例、来源和 F04 任务。模型访问在事务之外进行。恢复沿用同一个模型 requestId，复用已保存结果；采用时核对 owner、实例代次、原稿版本、任务身份和有效租约。人格版本、当前指针、初始基线与任务成功一起提交。

暂停保留进度；取消阻止后续采用，原稿仍在。已知失败/取消后可主动重试并形成新任务。未知结果会阻塞，即便先取消也不能绕过未知尝试检查重新发送。未知外部结果需要运维核对，本轮没有自动对账功能。模型调用成功也可能因引文无效而未被采用，两种状态分开记录。

## 公共接口与迁移

沿用认证和 `{code,data,message}`，owner 由服务端确定，命令和版本由 contracts 统一校验。

| 接口                                                               | 用途                                 |
| ------------------------------------------------------------------ | ------------------------------------ |
| `POST /api/companion-creations`                                    | 原稿或指定模板版本创建，返回持久任务 |
| `GET /api/companions`                                              | UUID 游标分页                        |
| `GET /api/companions/:id/persona`                                  | 当前/初始人格和整理状态              |
| `GET /api/companions/:id/persona/versions/:version?runtimeEpoch=1` | 精确回查不可变版本                   |
| `POST /api/companions/:id/persona/initialize`                      | 旧原稿启用或已知失败后主动重试       |
| `POST /api/companions/:id/persona/locks`                           | 约束修订，带代次和预期人格版本       |
| `POST/GET /api/persona-templates`                                  | 创建模板、分页查询                   |
| `GET /api/persona-templates/:id`                                   | 最新模板                             |
| `POST /api/persona-templates/:id/versions`                         | 乐观编辑、追加新版本                 |
| `GET /api/persona-templates/:id/versions/:version`                 | 模板历史版本                         |

F02 的 `POST /api/companions` 保留只保存原稿、不调用模型的语义，旧验收不会突然产生调用；Web 使用 `companion-creations`。任务控制沿用 F04，可运行 `pnpm tasks:config get <ID>` 查看。

追加 `0003_persona_foundations`：新增模板身份、模板版本、初始人格来源三张表，扩展人格文档、原因、前版、模型引用、修订命令字段。0000/0001/0002 原文与 hash 不变。旧行取得兼容字段默认值，不触发初始化调用。没有新增依赖。
