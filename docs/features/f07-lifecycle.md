# F07：消息删除、实例重置与删除

本功能实现架构 §13.6 的公共命令、持久限制和当前模块清理协议。比较基线为 `8f6b7d6`（F06）。所有终端共用数字 `code` 的 `{code,data,message}` 响应；清理不会调用模型，也不会清零已发生的模型用量。

## 网页验收

- 伴侣详情的「实例管理」提供「重置伴侣」「删除伴侣」，确认框显示对象和范围。重置保留实例身份、创建原稿、首次整理人格和初始明确约束，更新运行代次；后续修订的约束不替代初始种子。未完成初始整理时保留原稿及其初始约束，不额外调用模型。
- 重置清理完成后，从伴侣页面新建私聊。旧会话只读，不自动把旧原文、私有上下文或人格版本灌入新人生。删除实例后，私有资料不可读取，已发布共同原文保留最小参与者标识。
- 聊天气泡的「删除这条消息」选择当前页显示的确切原文/流式片段，最多 100 条。长回复跨页时只选择当前显示部分；服务端沿显式来源和模型上下文依赖传播，清除对应回复、转述、候选和待处理输入。其他独立原文保留。
- 顶部「清理记录」可查看操作、实际完成阶段、处理记录数和失败/暂停状态。清理中断时「继续清理」沿用同一范围与已提交进度，不重复重置代次。
- 在线聊天收到 `contentRevision` 或可用性变化时清空旧显示、分页、回执和在途读取，再取有效历史。清理期间暂时不读取原文，完成后显示「内容已删除」。离线终端重连后重新核对；无法擦除用户另行保存的截图或导出文件。

删除实例与删除共同原文是独立操作。删除 A 不自动删除 B 的合法经历，也不删除公共人设模板。未来记忆/索引/附件模块尚未落地，本版不会声称已经清理这些不存在的数据。

## 启动与升级

使用 Node 22.20+（推荐仓库 `.nvmrc` 的补丁版本）及 pnpm 11，在仓库根目录执行：

```bash
git pull origin dev
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

数据库和 Qdrant 继续沿用现有配置。使用 Compose 的完整部署：

```bash
docker compose --env-file .env -f deploy/compose.yaml up -d --build --wait
```

升级新增 `0005_lifecycle`，不修改已发布迁移。它为已有 F06 聊天上下文回填不含正文的 `chat_run_sources`，让重置删除私有上下文后，仍能追溯保留回复依赖的原文。不要删除数据卷来升级；也不要用旧版本程序继续写入已升级数据库。

服务启动后执行：

```bash
pnpm verify:f07
```

脚本创建两位验收实例、一个共同会话和三条原文，验证重置幂等、实例删除隔离、历史身份、明确原文删除与转述传播。只清理本次脚本返回 ID 对应的实例及内容，保留不含正文的历史身份和操作日志；不切换配置、不调用付费或测试模型。失败时保留当前状态供排查，不自动扩展清理范围。`VERIFY_BASE_URL` 可指定实际入口，密码仍从 `.env` 读取。

## 公共接口

| 接口                                    | 作用                                           |
| --------------------------------------- | ---------------------------------------------- |
| `POST /api/lifecycle`                   | 提交下述三种命令，限制与清理任务同事务生效     |
| `GET /api/lifecycle?limit=20&afterId=…` | UUID 分页查询最小日志                          |
| `GET /api/lifecycle/:id`                | 查询当前持久进度及执行任务                     |
| `POST /api/lifecycle/:id/retry`         | `{requestId}` 恢复失败、取消、阻塞或暂停的清理 |

实例命令：

```json
{
  "requestId": "此次命令的 UUID",
  "kind": "reset_companion",
  "companionId": "目标实例 UUID",
  "runtimeEpoch": 1,
  "expectedVersion": 1
}
```

`kind` 也可为 `delete_companion`。版本和代次必须使用当前接口所见值；冲突时重新核对目标，不能盲目替换版本后重发。

消息命令：

```json
{
  "requestId": "此次命令的 UUID",
  "kind": "delete_messages",
  "conversationId": "目标会话 UUID",
  "expectedVersion": 3,
  "messages": [{ "messageId": "确切原文 UUID", "contentVersion": 1 }]
}
```

`expectedVersion` 来自 `GET /api/conversations/:id` 的 `conversation.version`。一次选择同一会话 1–100 条；消息 ID 不可重复。网络重试沿用原 `requestId` 和完整载荷。同键异载荷返回 `40901`，版本不符 `40902`，运行代次不符 `40903`；清理限制返回 `40913`。已删除实例或失效来源返回 `404`，历史原文查询保留删除占位。

`pending` 仅表示限制已持久生效，`completed` 表示协议阶段全部完成。暂停、失败、取消后台任务都不撤销已经生效的限制；恢复会创建新的执行任务，稳定操作 ID 和已提交进度不变，旧尝试仍可核对。

## 一致性、配置和扩展

- 命令在模型配置头 → 部署调度头 → 会话/实例的锁顺序下提交限制、目标、代次/删除身份与任务。读取、派发、模型结果采用及片段发布再次核对范围。另一个进程的迟到输出也不能跨越限制；可信迟到用量仍结算。
- 协议 v1 有 13 个阶段：依赖传播、outbox、任务、模型候选、私聊上下文、读取回执、处理范围、接收批次、初始整理状态、人格父引用、人格版本、私有草稿、选定原文。每批修改与检查点在同一事务，失去租约则回滚该批。
- `.env` 的 `LIFECYCLE_BATCH_SIZE` 默认 100，范围 1–500；各阶段每次查询有界，依赖传播分别查询显式来源和聊天来源，各至多一批。不执行无界全表正文加载。
- 普通任务并发继续由 F04 配置控制；额外保留 **一个部署级数据库清理位置**，不增加模型并发和预算。`tasks.enabled=false` 时不领取清理，已经生效的限制仍保留。重启不会清零已用额度或任务尝试。
- 日志只存身份、版本、代次、协议版本、阶段和数量。消息正文物理置空，删除实例的人设快照置空、私有人格/接收记录清理；任务输入和模型候选清空。已发布消息身份、来源边、必要执行核对记录和计量仍保留，不把删掉的正文复制进审计记录。
- F02 当前只允许同一会话中的来源关联。没有来源关系的独立原文不会被语义猜测后删除；仅有 `replyToMessageId` 的会话定位也不等同于复制正文。转述或复制应登记 `sources`，模型回复的实际输入登记 `chat_run_sources`。
- 新派生模块必须接入 `LifecycleCleanupPage`、持久清理阶段，以及读取/派发/提交检查。增加阶段时维护协议版本并保留在途操作的旧阶段解释，不能直接重排 v1。文件、向量等外部清理应在事务外执行幂等动作，再提交检查点；仅删向量或仅打标不能算全部完成。
- 本功能是主库内生命周期基础，**不提供旧备份导入**。F23 负责独立于业务快照的最新生命周期记录、恢复围栏和历史备份策略；不能把普通 MySQL 卷重启验证描述为已防止旧备份恢复被删内容。
