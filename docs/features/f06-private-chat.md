# F06 Web 私聊、原文与流式回复

比较基线：`8f243dc`。本功能提供用户与单个伴侣的 Web 私聊，复用已有原文、模型配置/预算和持久任务。群聊、记忆提取、检索和自主成长仍按后续功能开发。

## 升级与验收

停止旧应用，在项目根目录执行：

```powershell
git pull --ff-only origin dev
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

MySQL 和 Qdrant 沿用现有服务；没有新增容器或 Redis 依赖。本次追加 `0004_private_chat`，旧 `0000`–`0003` 不改写。开发时访问 `http://localhost:5173`。

1. 进入任意伴侣详情，点击「开始聊天」。每次主动开始创建一个独立私聊，也可从导航「私聊」回到已有会话。
2. 发送近况或普通闲聊。原文先保存，回复逐步显示；生成期间可以继续发送补充，旧轮已发布文字保留，新轮使用最新原文和已说出的部分。
3. 点击「停止回复」，当前轮次停止发布；旧停止命令不会停止后来的新一轮。刷新或离开页面只断开接收连接，不取消后端生成。
4. 刷新后查看历史；暂时断网再恢复，页面自动带序号重连。发送结果不明确时保留输入，重试使用同一命令身份，避免重复原文。
5. 原文超过模型预算、调用失败或结果未知时查看状态提示。未知调用不自动重发，已保存原文和已发布片段仍然保留。

默认 test 模型输出「测试模型已收到：…」，只验收链路；它不具备实际聊天、理解地址纠正或人格扮演能力。页面明确标注测试模式。没有用这些测试结果宣称真实模型语义效果。

```powershell
pnpm verify:f06
```

脚本通过 13 项公开 HTTP 检查，保留一位「F06 验收」伴侣、一个私聊、两条用户原文及回复。只允许 chat 使用 test，不切换配置、不调用付费模型，也不删除既有数据。是否合并两条输入取决于实际等待参数和调度时机，通常产生 1–2 次测试调用。流式传输、跨进程打断及重连另外由后端集成测试和浏览器测试覆盖。

Docker 整套部署仍使用：

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build --wait
```

反向代理需允许 `/api/chats/:id/events` 的 SSE 持续传输，关闭该路径的响应缓冲并设置足够长的读取超时；服务发送 `X-Accel-Buffering: no`，每 10 秒发送心跳。代理不能把认证错误改写成成功流响应。既有登录会话仍保存在单后端进程，重启后需要重新登录；多进程领域测试不代表已支持负载均衡登录。

## 模型与集中配置

在 `.env.models` 的供应商登记中声明 `streaming: true` 才启用兼容 Chat Completions SSE。省略或 false 时明确整段返回，不把完整响应伪装成实时流。需要兼容 `stream_options.include_usage`、文本增量和 `[DONE]`；供应商不支持时可关闭 streaming。缺少可信用量时保守保留额度，不当作零费用。

chat 模型名称、价格、输入/输出上限等仍由 `pnpm models:config` 维护，具体命令见 F03。新安装直接使用 `chat-v1 / chat-v1 / utf8-v1` 定义，开始聊天不另改全局配置版本；输入上限为 32768，输出上限继续为 512。输入计量采用 UTF-8 字节保守上界，并非准确 tokenizer。旧部署首次实际聊天只把 `probe-v1 / probe-v1 / utf8-v1` 占位定义追加绑定为聊天定义，保留模型、价格、限额和历史，自定义定义不被覆盖。此绑定属于一次配置发布，旧部署应先完成已排队的人格初始化再开始首次聊天，避免旧配置任务因版本冲突失败；失败时原稿仍保留。旧部署需要更多上下文时应显式调整 chat 输入限额。

聊天资源参数集中在 `.env` 的 `CHAT_CONFIG_JSON`，修改后重启；新轮次保存配置快照，旧轮不混用新设置。有效参数可通过 `GET /api/chats/configuration` 查看：

| 参数                | 默认值  | 作用                                             |
| ------------------- | ------- | ------------------------------------------------ |
| mergeWindowMs       | 300 ms  | 连续用户输入的短合并等待                         |
| maxMergeWaitMs      | 1500 ms | 连续补充不会无限延后生成；实际领取还受队列影响   |
| historyMessages     | 200     | 每次上下文选择最多检查的最近原文条数             |
| publishChunkChars   | 256     | 正式原文片段的最大 UTF-16 长度，不拆开表情代理对 |
| publishIntervalMs   | 100 ms  | 小增量合并等待，首段立即尝试发布                 |
| eventPollMs         | 250 ms  | SSE 查询持久新原文的间隔                         |
| maxEventConnections | 8       | 单后端允许的同时事件连接数                       |

任务的轮询、并发、租约和重试继续由 `pnpm tasks:config` 控制，模型的并发和金额仍受 F03 双层预算约束。合并窗口不是判断用户一定说完的依据，不能代替新的补充打断。

## 数据与执行边界

- 用户原文保存、正式发布、待整理 outbox、回复任务及当前轮次切换在同一事务提交。网络重试复用发送身份；新补充撤销旧轮租约，数据库检查能挡住另一进程的迟到输出。
- 流式候选按有界片段保存为不可变 `messages`，来源为 `model_output`。`chat_segments` 只保存消息/轮次引用与位置；页面把同轮连续片段合成气泡，原文不重复存一份。
- 每次发布锁顺序固定为模型配置头 → 调度头 → 会话/实例。调用取消、轮次替换、人格版本变化和租约过期均阻止后续发布；未发布缓冲不在失败收尾时变成发言。模型访问和 SSE 网络传输不持有数据库事务。
- `chat_runs` 引用持久任务，保存当前输入边界、配置快照、上下文来源和模式。恢复沿用同一模型 requestId；已确认成功的完整候选只补发尚未发布且与已有前缀一致的部分，未知结果保持阻塞。
- 上下文包含当前人格、明确约束、当前会话可见的最新原文、用户显示名称及 Web 环境。整理后只使用当前 document；旧原稿版本尚未整理时使用该当前版本原稿，不自动调用人格整理。没有虚构记忆、关系状态或工具能力。
- 选取原文后固定消息 ID/版本和人格版本，登记伴侣实际取得正文的精确范围。超预算时逐组省略更早交流并记录省略边界，不能丢弃本轮待回应原文或人格约束后继续调用。完整上下文必要部分仍放不下时返回持久原因 `api_40003`。
- SSE 的消息事件 ID 直接使用正式发布序号，按游标重放，每批最多 50 条；状态事件读取持久快照。送达回执由页面显示原文后单独提交，按终端和确切消息版本幂等。发布、实例取得正文、终端送达、模型理解和记忆整理不是同一状态。
- 浏览器历史按 50 条翻页，实时页最多保留 100 条；较早历史不会被新消息自动顶掉。不在 localStorage 保存私密对话。聊天会话的写入口统一，F02 管理保存/发布接口对这些会话返回 `40912`，避免绕过补充打断流程。

## 公共接口

所有 JSON 响应仍为 `{ code, data, message }`，code 为共享数字码。SSE 的每个 data 帧也使用同一外层；认证失败、游标错误、连接数超限在流开始前返回普通错误响应。

| 接口                           | 作用                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------ |
| POST /api/chats                | `{requestId, companionId, runtimeEpoch, title}` 创建双人私聊                   |
| GET /api/chats                 | UUID 分页列出私聊                                                              |
| GET /api/chats/:id             | 当前轮次、精确上下文来源与任务状态                                             |
| POST /api/chats/:id/messages   | `{requestId, text}` 保存并安排回复，正文最多 4000 个 UTF-16 单元               |
| GET /api/chats/:id/messages    | 最近历史页；beforeSequence 向前翻页                                            |
| GET /api/chats/:id/events      | afterSequence 或 Last-Event-ID 重连；message 有序号，state 是最新快照          |
| POST /api/chats/:id/stop       | `{runId}` 只停止目标轮次                                                       |
| POST /api/chats/:id/deliveries | `{terminalId, messages:[{messageId,contentVersion}]}` 确认送达，不表示人类已读 |
| GET /api/chats/configuration   | 集中配置的非敏感参数                                                           |

新表为 chat_threads、chat_runs、chat_segments、chat_deliveries；新增任务类型 chat_reply、原文来源 model_output，沿用旧任务、调用、原文、读取和 outbox 表。Qdrant 在本功能仍只承担基础服务职责，没有写入业务向量。
