# F24 后端发布验收与部署

后端实现覆盖 F01–F23，发布验收将可复现的程序行为、受限容量和真实模型语义分别记录。实际部署使用 Node.js 22.23.4、MySQL 8.4.9、Qdrant 1.18.3 和 Redis 8。

## 新部署和升级

1. 按 README 初始化环境和模型配置，使用独立的应用、存储和登录凭据。Compose 启动 MySQL、Qdrant、Redis 后执行当前版本的迁移，再启动后端。`GET /api/health/ready` 对照数据库版本与依赖健康状态。后端运行许可可并行，恢复、备份和迁移在部署离线后运行。
2. 升级现有部署时先停止后端，按 F23 备份业务数据和独立限制日志，随后应用追加迁移并启动。部署运维确认线包括模型 JSON 的启动检查、登录、聊天及管理入口、终端和附件。恢复过程使用与备份一致的发布版本，完成后再升级。[F23 模板、备份与恢复](f23-data-archive.md)
3. 持久挂载业务文件和独立日志。对公网部署使用 HTTPS 和独立账号凭据。普通验证使用测试模型与隔离库。真实模型评估需要另建账号、数据目录和数据库，并显式设定角色价格及全局窗口上限。

## 验收入口

| 命令                         | 范围                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| `pnpm verify:release`        | 格式以外的静态检查、全量构建、后端集成及浏览器协议                                       |
| `pnpm format:check`          | 全仓格式                                                                                 |
| `pnpm bench:release`         | 隔离测试模型下的持久聊天、SSE 首条正式回复、任务完成和用量                               |
| `pnpm bench:release:vectors` | 真实 Qdrant 的定量写入、确切点数与范围过滤                                               |
| `pnpm eval:release`          | 带费用上限的固定中文真实模型语料，输出当前事实、旧事实误用、证据覆盖、别名和实例隐私检查 |

集成和浏览器需要 `TEST_DATABASE_URL`、`TEST_REDIS_URL`、`TEST_QDRANT_URL` 与 `TEST_QDRANT_API_KEY`。使用已安装 Chromium 时设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。隔离 MySQL 测试角色需要创建临时库，业务部署账号使用各自库的权限即可。

容量测试通过 `F24_BASE_URL`、`F24_ADMIN_PASSWORD`、`F24_ROUNDS` 和 `F24_CONCURRENCY` 配置。准备没有伴侣的独立部署，固定本地回环验收端口。将模型文件全部设置为测试模式，费用额度设为 0，聊天请求和 token 上限覆盖预定轮数。向量脚本使用 `F24_QDRANT_URL`、`F24_QDRANT_KEY`、`F24_VECTOR_POINTS`，测试结束后自动移除本次生成的集合。

真实模型评估使用 `F24_BASE_URL`、`F24_ADMIN_PASSWORD`、`F24_MODEL_BUDGET_MICROS`。部署模型文件须已启用、定价并记录聊天、记忆提取和向量编码角色。当天已使用模型的部署会被拒绝，费用上限不超过显式授权金额。语料由程序创建，报告包含实际配置版本、模型、回答、确切来源、P50、P95 和计量。长周期人格连续性、反思和真实材料抽样需要独立人工复核。

## 应用回归

桌面和移动浏览器共 32 个场景分批验证。移动端删除、重置和终止的组合场景首轮在测试总时限 30 秒处中断，单独复跑通过。备份和迁移在已有运行服务的数据库上被拒绝，两处运行服务可以共用同一个测试库。

任务的退避验收使用实际持久化的重试时间，独立进程的就绪窗口覆盖容器冷启动。已保存检查点后的强制终止、在途模型未知结果和迟到用量结算在独立测试库再次通过。

## 隔离容器实测

聊天压测使用确定性模型和真实 MySQL、Redis、Qdrant。四个容器的 CPU 配额合计 2 核，内存上限合计 4 GiB。分配为后端 0.75 核和 1 GiB、MySQL 0.75 核和 1.5 GiB、Qdrant 0.35 核和 1 GiB、Redis 0.15 核和 0.5 GiB。调度轮询设为 250 ms，后台模型并发保留为 1。

| 观测                       | 结果                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------ |
| 聊天负载                   | 4 个并发会话，480 轮全部完成，778.4 秒，0.62 轮/秒                                   |
| 原文确认 P50 / P95         | 61.5 / 205.6 ms                                                                      |
| SSE 首条正式回复 P50 / P95 | 5.37 / 11.47 秒                                                                      |
| 任务完成 P50 / P95         | 5.70 / 12.07 秒                                                                      |
| 容器内存同时峰值           | 756.0 MiB                                                                            |
| 测试模型用量               | 566 次，11,320 token，实际外部费用 0                                                 |
| Qdrant                     | 10,000 个 64 维合成点，1.05 秒写入；100 次带范围的精确查询，P50 3.33 ms，P95 8.59 ms |

真实发布镜像还完成了 79 张业务表、64,729 行、1,440 条原文与生成片段的离线往返。归档包为 24,271,688 字节，导出 57.92 秒、校验 28.47 秒、恢复 101.07 秒。MySQL 业务库已分配表和索引的空间从源库 86,573,056 字节到恢复目标 77,578,240 字节。离线维护沿用相同存储容器，命令本身未设独立 CPU 配额。该负载包无附件，带附件和最新限制的恢复由 F23 单独验收。

该容量样本记录这套隔离资源和测试配置下的实际等待时间。真实提供商的延迟、费用和语义效果仍需目标部署的模型配置及费用上限。目标主机的磁盘、网络和进程调度也需对应测量数据。
