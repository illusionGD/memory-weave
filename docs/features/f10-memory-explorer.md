# F10：记忆浏览、时间线与关系图谱

比较基线：`7921ce9`（已确认的 F10 方案）。入口为管理后台的「记忆记录 → 选择伴侣 → 浏览记忆」。本版只做查看与追溯；纠错继续通过聊天补充，由伴侣自主整理。聊天端保持独立。

## 启动与升级

```bash
git pull --ff-only origin dev
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

开发后台默认 `http://127.0.0.1:5174/admin/`，以启动终端输出为准。完整 Docker 部署使用原有 `.env` 和数据卷：

```bash
docker compose --env-file .env -f deploy/compose.yaml up -d --build --wait
```

本版追加 `0009_memory_explorer`，只给 `memory_versions` 增加记录时间和前置版本查询索引，不改写 `0000–0008` 或已有记忆。MySQL 仍是权威数据源，Qdrant 仍用于聊天检索；后台浏览无需向量调用，也不新增图数据库。只回滚应用不能删除已应用的迁移历史；完整回退按已有备份恢复流程执行。

## 页面与验收步骤

1. 为同一伴侣建立两段私聊，整理地址、偏好与故事内容。在后台选中该伴侣，默认汇总当前人生的全部私聊；可选单个会话。群聊必须明确选择，其他伴侣与旧人生不混入。
2. 用关键词、类别、主张类型、有效状态、现实/创作、故事名称和记下时间筛选。关键词是记忆正文中的字面包含匹配，`%` 等字符不会变成 SQL 通配符；这里不做语义检索。
3. 查看来源与历史：卡片区分当前/历史版本、陈述/推测/创作，详情显示整理原因、准确引文和完整原文。证据、历史、会话选项分别分页；旧的整理批次入口仍可访问。
4. 时间线按记下时间倒序，同一毫秒按稳定版本 ID 排序。新增认识、合并、情况变化、纠正旧记录、保留分歧分别显示；「小时候」「昨天」保留为经历描述，不伪造精确日期。
5. 从任意记忆或历史版本进入图谱，点击节点展开一层。记忆连接其版本；版本连接精确原文、整理上下文、明确修订和一般依赖。只有持久化的 `previousVersionId` 才标为修订；关系不代表主张已经证实。推测内容有独立标识。
6. 图谱可缩放、拖动、适应画布，也提供可键盘操作的节点和关系列表。手机使用同样的功能，高级筛选默认收起。
7. 删除测试来源或重置实例，已打开的列表、详情、引文和图谱应清空；迟到响应不得恢复旧正文。刷新或重启后仍不可读。不要用真实伴侣数据试验清理。

默认 `test` 模型不产生记忆候选，因此空页面是正常结果。要验证真实提取效果，按 F03 配置 memory 模型；本版不改变模型配置或提高部署预算。

## 可复现的非空验收

`pnpm verify:f10` 在随机隔离数据库中，通过公开 HTTP 与本地模型协议 fixture 生成「杭州 → 苏州 → 纠正南京」、雨天推测和月之旅创作等记录，运行桌面/手机浏览器流程，最后删除自己创建的数据库。不连接付费供应商，不改真实伴侣数据，也不在日常数据库留下演示记录。

先准备独立测试 MySQL 账号（具备临时库创建/删除权限）和测试 Qdrant；PowerShell 示例：

```powershell
$env:TEST_DATABASE_URL = 'mysql://测试账号:测试密码@127.0.0.1:3306/mysql'
$env:TEST_QDRANT_URL = 'http://127.0.0.1:6333'
$env:TEST_QDRANT_API_KEY = '测试服务的密钥'
pnpm exec playwright install chromium
pnpm verify:f10
pnpm exec playwright show-report
```

测试服务使用本机 `4173`、`4174`、`4185` 端口；运行前需空闲。脚本会先构建三个应用和共享包。截图和失败 trace 位于 `test-results`，报告位于 `playwright-report`。也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已有 Chromium。该命令证明查询、展示和生命周期隔离，不代表真实模型提取质量通过验收。

## 接口与读取边界

统一前缀：`/api/companions/:id/memory-explorer`。沿用登录、同源保护、数字 `{code,data,message}` 与公共中文注释契约。

| 方法与路径           | 用途                                         |
| -------------------- | -------------------------------------------- |
| `GET /conversations` | 当前实例和人生的会话选项，游标分页           |
| `GET /entries`       | 当前记忆列表和组合筛选                       |
| `GET /timeline`      | 所有语义版本的记录时间线                     |
| `GET /graph`         | 指定记忆或版本的一层邻接关系                 |
| `POST /validate`     | 有界核对已展示版本的读取指纹，不产生业务写入 |

`runtimeEpoch` 必填。`conversationId` 省略时只允许该用户与该伴侣的私聊汇总，传入时限定单个有权限的会话。每次查询核对 owner、伴侣、人生代次、成员、会话生命周期及来源可见性。读取指纹和游标都不能授予权限。

列表/时间线默认每页 20，API 最大 50；游标绑定视图、范围、筛选和页大小，固定本轮版本记录时间上界。当前有效状态仍实时核对，不把游标描述成历史事务快照；有新修订时刷新重新开始。图谱按稳定关系身份去重，默认每次 20 条边，API 最多 48 条边、50 个节点，前端画布最多 200 节点/400 边。证据追加后刷新可查看完整新关系，不承诺旧图游标包含并发新增的证据。

这些上限以及 3 秒可见页核对间隔集中在 contracts 的 `MEMORY_EXPLORER_LIMITS`。轮询最多核对 300 个已加载引用，只查询状态与版本字段；不扫描全部历史，不读取正文，不访问模型或 Qdrant。后台标签页暂停核对，重新可见时先验证；首次后台加载被丢弃时重新初始化。网络失败或离线也清除旧正文，恢复连接后可手动刷新。当前通过轮询发现其他终端的变更，并非实时推送，发现延迟为轮询间隔加请求耗时。

前端所有新响应在采用前再次验证现有与新增引用；范围切换、失效、隐藏及卸载会使旧请求失效。页面不持久缓存记忆正文。后端所有图关系来自 MySQL 表，使用 [Cytoscape.js](https://js.cytoscape.org/) 3.34.4（MIT）按需加载绘制，无持续物理动画和外部图服务。

## 性能与验证记录

性能脚本：`apps/server/test/support/benchmark-memory-explorer.ts`。先构建 contracts，设置显式测试连接，再执行：

```bash
pnpm --filter @memory-weave/server exec tsx --tsconfig tsconfig.json test/support/benchmark-memory-explorer.ts /tmp/mw-f10-benchmark.json
```

脚本只在自己创建的随机库中，经 HTTP 创建 1,000 条记忆、1,000 个版本、134 条原文，其中一条记忆额外合并 50 次证据。它在该临时库移除/恢复两个新索引做对照，记录每类 30 次 HTTP 端到端 P50/P95，另测 32 次、4 并发的列表请求；查询计划输出是排序和前置版本定位的子查询，不冒充整条联合查询计划。结束后清理隔离库。

2026-10-31 最终测量：Node 22.23.4，环境暴露 5 个 CPU（AMD EPYC 9V74），Node 进程峰值 RSS 约 312 MiB（不包含 MySQL/Qdrant）。正式索引下的 HTTP 端到端结果：

| 查询               | P50 / 毫秒 | P95 / 毫秒 |
| ------------------ | ---------: | ---------: |
| 当前列表 20 条     |      62.78 |      73.18 |
| 时间线 20 条       |      57.70 |      75.84 |
| 关键词列表 20 条   |      50.07 |      61.46 |
| 图谱 48 条边       |      16.89 |      18.70 |
| 状态核对 50 个引用 |      11.84 |      14.51 |
| 列表 4 并发        |     149.32 |     227.33 |

排序子查询改用 `memory_version_time` 反向索引扫描，避免 filesort；前置版本定位改用 `memory_version_previous`。完整原始数据保留在 [性能记录](../../evaluations/memory-explorer/README.md)。两轮曾出现秒级波动：初测索引后时间线 P95 1,150 ms，最终对照的无新索引列表 P95 1,009 ms；最终索引版未复现这些峰值，不能据此保证延迟上限或声称固定倍数提升。

当前验证对象是共享托管开发机及其 MySQL 容器，不代表用户 2 核 4 GB 云服务器容量。关键词 JSON 包含匹配仍会扫描授权范围中的候选，尚未验证十万级数据，也未实现全文索引或独立读服务。

- 格式、lint、类型检查与生产构建通过。
- 5 组后端集成测试、44 个用例通过：本功能 5 个，加记忆整理、检索、生命周期、迁移回归。桌面/手机浏览器本功能 4 个、相关回归 8 个通过；覆盖后台首次加载、精确引文、图谱、来源删除和迟到响应。
- Docker 保留数据卷升级：迁移首次 `applied=1`、重跑 `applied=0`。升级和重启前后 24 个伴侣、26 段会话、77 个任务、36 个模型调用、30 个记忆范围、4 个记忆版本、3 个索引记录的公开快照一致，Qdrant 点仍可读取；头像字节和初始人格一致。
- 用新浏览接口读取升级前已有的非空记忆、两条时间线版本和五节点来源图，并校验读取指纹，重启后同样通过。未部署到用户云服务器。
