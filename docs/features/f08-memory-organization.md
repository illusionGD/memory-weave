# F08：批量记忆整理

> 2026-10-30 入口更新：聊天端仅浏览记忆与来源；手动整理、批次进度和重试移至管理端「记忆记录」。 详见 [前端拆分说明](frontend-split.md)。

比较基线：`22b0652`（F07）。伴侣现在会在后台把已发布聊天整理成有来源的记忆；原文、语义版本和逐实例进度分别保存。F08 不修改初始人生或当前人格。跨会话混合检索、未整理补读和回复注入按 F09；完整时间线、关系图谱与管理按 F10。

## 启动与网页验收

Node 22.20+、pnpm 11，在仓库根目录执行：

```bash
git pull origin dev
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

使用现有 MySQL、Qdrant 即可。完整 Docker 部署：

```bash
docker compose --env-file .env -f deploy/compose.yaml up -d --build --wait
```

本版追加 `0006_memory_organization`，不修改 0000–0005。保留数据卷升级；旧 `pending` 范围保留且可批量整理，旧 `handler_unavailable` 占位任务作为历史保留，不会逐条重发模型请求。

1. 打开一个当前代次的私聊，发送几条消息。
2. 点击「这段对话的记忆」，等待自动整理或点击「现在整理」。该按钮只提前唤醒一个批次，不需要逐条批准记忆。
3. 查看「留下的内容」「来源与历史」「整理进度」。事实变化和原先记错分别显示；分歧保留历史主张，不显示为唯一确定事实。
4. 查看完整来源原文，刷新页面确认保留。记忆、版本、证据与批次均分页；页面定期重新验证有效性。
5. 删除聊天来源后，相关记忆立即受会话清理限制，完成清理后显示已失效；其他会话保留。重置 A 不清理 B 的合法记忆。

默认 `test` adapter 返回零候选，仍完成精确范围。它用于验证流程，不假装理解语义；结构化新增、合并、修订、分歧和来源拒绝由真实 HTTP fixture 集成测试覆盖，真实模型质量仍需专项评估。

```bash
pnpm verify:f08
```

脚本创建两位验收实例、共同会话、两条原文，只允许已启用的 `test` 记忆模型；不切换真实模型、不删除已有数据。若仍是旧 `probe-v1` 占位定义，首次明确整理会追加一版记忆定义绑定，保留供应商、模型、价格、预算与历史。`VERIFY_BASE_URL` 可指定实际入口。旧 F02/F06/F07 验收脚本也会拒绝启用中的真实记忆模型，避免验收原文触发额外付费整理；不会替部署者改模型配置。自定义自动整理阈值很短时，B 也可能自行完成，脚本验证它使用自己的批次。

## 模型配置与升级行为

统一模型入口的 `memory` 角色使用 `structured` 能力，定义为 `memory-extraction-v1`（prompt/schema），预处理 `utf8-v1`。新部署默认输入上限 32768 token、输出上限 4096 token。供应商、价格、超时、限额仍通过现有模型配置维护；使用真实模型前按 F03 登记供应商并配置此角色。

旧部署的模型配置不会因后台轮询被静默覆盖。遇到旧占位定义时，记录 `memory_configuration_required`；在记忆页「重新整理这一批」或明确「现在整理」可启用已知新定义。启用不会上调旧配置的输入/输出限额，必要时自行调整。未知版本不自动替换。后续普通批次自动运行，无需用户确认。更换模型不会自动重做已完成历史；正式使用前先配置真实 memory 模型，test 数据适合在验收实例中验证。

模型变更后，尚未发出的旧配置任务可能因版本变化失败；显式重试会保留旧任务并按当前配置重新分批。已保存的模型结果继续使用原调用身份恢复；未知外部结果保持阻塞，禁止换键补发。切换记忆提取模型、提示词或 schema 需要回归相同语料，尤其检查时间、对象、纠正和虚构边界。

## 集中配置与调度

`.env` 的 `MEMORY_CONFIG_JSON` 由 dev、start 和 Compose 共用，修改后重启。每批保存参数快照。默认值：

| 参数               | 默认值 | 含义                                      |
| ------------------ | ------ | ----------------------------------------- |
| enabled            | true   | 是否自动安排批次；关闭后仍可显式整理      |
| idleMs             | 30000  | 停聊 30 秒触发                            |
| maxWaitMs          | 300000 | 最早待办最多等待 5 分钟                   |
| messageThreshold   | 16     | 达到 16 条触发                            |
| characterThreshold | 12000  | 达到约 1.2 万字符触发                     |
| maxMessages        | 24     | 单批最多 24 条完整原文                    |
| maxInputCharacters | 24000  | 固定输入字符上限，另受模型 token 上限约束 |
| contextMessages    | 4      | 同会话最多补充 4 条前置原文               |
| relatedMemories    | 12     | 同会话最多提供 12 份近期旧记忆            |

空闲、数量、体积、最长等待任一满足即可安排。容量不足、暂停、失败或未知结果可能继续等待，阈值不是完成时间承诺。单条超限时阻塞，不能截断后冒充整条完成。F08 的旧记忆候选限定同会话、按近期有界选取；更大规模的相关性选择与跨会话检索由 F09 接入。

任务调度器为记忆保留一个独立后台位置，清理也有一个独立位置；`maxConcurrent` 管理普通任务。模型请求仍受 F03 全局并发、后台并发和预算约束，因此不会绕过部署资源上限。部署者若主动将模型总并发限制为 1，聊天仍可能等待模型容量。

每个伴侣同时只有一个未关闭记忆批次，避免不同会话竞相修订同一认识。失败保留范围与原因；不会为了处理后面的消息，假称前面的内容已经完成。已知失败可显式重新分批；原任务、调用与用量不清零。暂停任务沿 F04 接口恢复。

## 原文、记忆和来源

| 结果       | 持久行为                                                             |
| ---------- | -------------------------------------------------------------------- |
| 新增       | 新记忆 ID 与第一版正文                                               |
| 合并       | 同一 ID 新增语义版本；完全相同的当前内容只追加精确证据               |
| 修订       | 同一 ID 新增版本，区分 change（情况变化）和 correction（旧主张有误） |
| 分歧       | 保存新旧版本及关系，当前标记 disputed，不强行选一个真相              |
| 暂不成条目 | 保留原文、批次结果与完成范围，允许整个批次零条目                     |

正文包含对象、用途、主张类别、现实/虚构及故事范围、认识来源和时间描述。时间保留原文精度或相对表达，未知留空；入库时间独立记录。短暂情绪使用 state，不提升为长期人格；用户要求不自动成为共同约定。虚构设定必须保留故事范围，不能与现实事实合并。

模型只提出候选。采用前校验来源 ID、版本、逐字引用、实例/代次、可见性、目标记忆版本和现实范围。每项至少包含一条本批新原文证据；一次违反校验，整批结果与进度回滚。程序不能仅凭结构校验证明模型语义正确，语义质量依赖回归样本与后续评估。

MySQL 保存五张表：`memory_batches` 固定输入和结果、`memory_entries` 稳定记忆头、`memory_versions` 只追加语义版本、`memory_evidence` 精确消息引用、`memory_dependencies` 旧版本依赖。依赖只引用已有旧版本，不反复复制全部祖先正文或来源；同文去重不新增依赖环。转述和重复表达作为来源记录，F08 不把次数当作独立佐证权重。Qdrant 本轮不写业务索引。

每个 `processing_ranges` 属于一个实例、代次、会话和确切原文版本，状态为 pending / processing / processed。结果、五类计数、范围完成和任务完成同事务；不以最大序号越过空洞。原文接收回执、记忆整理完成和用户终端送达分别记录。

## 删除与恢复

生命周期协议 v2 在原文清理前新增记忆阶段，v1 的阶段编号及旧操作恢复保持不变。来源删除沿原文依赖与旧记忆版本依赖传播；内容、候选、批次输入和精确证据清除，当前记忆失效时不回退到可能过期的旧事实。

新结论保守依赖实际提供的上下文及旧版本。删除其中一项可能使同批相关结论一起失效；仍存活的独立原文重新进入待整理范围，供后续重新提取。实例重置/删除仅清除该实例旧代次私有内容，共同原文、其他实例合法经历和全局计量保留。

任务派发、心跳和提交都检查生命周期限制。强杀后可复用已经保存的模型结果；迟到候选无法写回已删除范围，但可信用量仍结算。备份恢复的完整收口仍按 F23，不能用旧程序写入已升级数据库。

## 公共接口

统一返回 `{code,data,message}`，数字 code 沿用 contracts。以下查询须带 `runtimeEpoch`、`conversationId`，分页可用 `limit`、`afterId`：

| 接口                                                                      | 用途                                               |
| ------------------------------------------------------------------------- | -------------------------------------------------- |
| GET `/api/companions/:id/memories`                                        | 当前记忆分页                                       |
| GET `/api/companions/:id/memories/:memoryId`                              | 当前与历史版本分页                                 |
| GET `/api/companions/:id/memories/:memoryId/versions/:versionId/evidence` | 版本证据分页                                       |
| GET `/api/companions/:id/memories/batches`                                | 批次状态、结果及集中参数                           |
| POST `/api/companions/:id/memories/organize`                              | `{requestId,runtimeEpoch,conversationId}` 提前整理 |
| POST `/api/companions/:id/memories/batches/:batchId/retry`                | 同形命令，明确重试已知失败                         |

精确原文继续通过 F02 的 `/api/companions/:id/sources/:messageId?runtimeEpoch=…&contentVersion=…` 回查。接口不导出租约或批次私有输入；失效正文只返回无内容记录。
