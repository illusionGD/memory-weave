# F20 自主同伴交流

同伴可以在用户已授权的范围内发现彼此、提出邀请、接受或推迟邀请，以及在有效依据支持下离开群聊。默认关闭实例发现和会话自主发言。`PEER_CONFIG_JSON` 可以禁用整个模块，并配置每场调用次数、单次输出 token、每场美元微单位预算和话题冷却时间。默认值分别为 6 次、500 token、50,000 美元微单位和 1 小时。每次实际派发仍计入 F19 的共享实例日额度，使用后台模型并发池。

## 接口与状态

- `GET /api/peer-profiles` 返回同一部署账号下明确公开的实例简介。`GET`、`PUT /api/companions/:id/peer-policy` 管理实例授权、公开简介、邀约决定和退出许可。
- `GET`、`PUT /api/conversations/:id/peer-policy` 管理会话授权。`GET /api/conversations/:id/peer-sessions` 返回实际触发消息、调用和费用。逐位的正式发表、静默、退出和跳过状态由 `GET /api/conversations/:id/turns/:turnId` 返回。
- 自主探索可根据公开简介提出邀约，受邀实例预设接受、拒绝或推迟。第三位接受后沿用 F17 建立独立的群聊，原私聊原文和历史授权仍由 F17 控制。
- 自主场次从用户或管理员代角色已发布的话题开始。相同消息只触发一次，冷却期内同成员同文本不会在另一个群聊重新开场。每步校验当前权限，用户插话通过 F18 终止过期轮次。
- 退出需要实例及群聊都许可，并引用同会话中至少两条仍可见的已发布消息，其中至少一条由自己发表。额度耗尽后保留已发表内容和成员状态。

## 验证

在与真实数据隔离的 MySQL、Redis 上运行 `pnpm verify:f20`。场景覆盖同场及角色额度、话题重开、公开范围及实际接受邀请、授权退出。测试 adapter 提供确定性候选，系统处理真实发布、持久化和计量。部署需先运行 `pnpm db:migrate` 应用 `0010_peer_talk`。
