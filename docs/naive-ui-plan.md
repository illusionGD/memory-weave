# Naive UI 双端组件替换方案

状态：范围已确认，完整方案待 review；尚未安装依赖或修改界面代码。日期：2026-11-02。

## 1. 已确认的范围

- 用户要求前端 UI 尽量使用 Naive UI，并选择「本轮替换两端现有通用控件」。实施和验收顺序为后台 → 聊天端。
- `apps/admin` 保持后台管理风格；`apps/web` 保持已确认的星空、月亮、简洁聊天气泡和扁平按钮风格。
- 按既有约定，完整方案 review 并获准后才开始实现；已确认批次内部的小任务不重复请求批准。

当前盘点：聊天端 17 个 Vue 文件，后台 20 个 Vue 文件；两端共有 100 个原生 button 标签，以及输入框、选择器、表格和折叠内容。两端均未安装通用 UI 库，Element Plus 只出现在原技术选型中。统计用于说明范围，不要求把每一个原生 HTML 标签机械替换。

## 2. 使用方式与视觉方案

### 2.1 组件映射

| 当前场景                     | 建议使用                                          | 保留的行为                                                                 |
| ---------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------- |
| 后台导航、常规布局与面板     | 按页面需要使用 `NMenu`、`NLayout`、`NCard`        | 原路由、选中态、手机收纳和页面层级                                         |
| 按钮、操作入口               | `NButton`、按需使用 `NButtonGroup`                | 禁用、提交、加载状态；导航保留真实链接语义                                 |
| 表单、单行/多行输入          | `NForm`、`NFormItem`、`NInput`                    | 继续使用 contracts 中的 Zod 规则；密码属性、长度限制、中文输入法与键盘提交 |
| 会话/类别/状态筛选、时间范围 | `NSelect`、`NDatePicker`                          | 空筛选值和默认值；本地时间选择后转换为 UTC 请求                            |
| 后台数据表格                 | `NDataTable`                                      | 服务端游标、稳定行标识、已有操作与移动端横向阅读                           |
| 状态、空内容和等待           | `NTag`、`NEmpty`、`NSpin` / `NSkeleton`、`NAlert` | 页面错误持续可见；状态仍与实际请求或任务一致                               |
| 操作反馈与确认               | `NMessageProvider`、`NDialogProvider`             | 确认目标与影响、取消不发请求、避免重复提交；失败信息可继续查看             |
| 头像显示与选择               | `NAvatar`、`NUpload`                              | 选图预览后手动保存；继续通过已有客户端上传二进制图片                       |
| 折叠资料、来源与筛选         | `NCollapse`                                       | 可达的标题、展开状态、键盘操作、原文与来源追溯                             |

星空 SVG、月亮、聊天气泡、滚动容器和品牌装饰继续由页面实现；图谱保留 Cytoscape。语义布局标签和库内部需要的原生元素继续使用。已有游标接口没有总页数，不接入要求任意跳页的分页交互；仍使用「加载更多」或已有的前后页行为。

### 2.2 主题与集成

- 两个应用分别安装同一个固定版本，通过根目录 pnpm catalog 统一维护；拟使用 `naive-ui@2.45.3`。
- 在各自应用根部接入 `NConfigProvider`、中文语言与日期语言配置，以及消息/对话框 provider。页面显式按需导入组件，依靠构建裁剪；首轮不引入全局全量注册或额外自动导入工具。
- 聊天端采用深色基础主题和集中维护的 `themeOverrides`，对齐现有蓝紫色、间距和圆角；按钮采用扁平样式。后台采用浅色内容区与蓝灰色强调色，保留深色侧栏。
- 主题配置放在各应用 `src/assets/styles`；业务组件仍位于各自项目，不跨应用引用 UI，也不向 browser-client 或 contracts 引入 Vue / Naive UI。
- 对照实际使用移除旧按钮、输入框和表格样式。检查 reset 中的全局 `svg`、`button` 等规则，避免污染组件图标和状态；优先通过主题与公开组件属性定制。
- 组件渲染后继续保留可访问名称、焦点可见性、表单标签、错误提示和减少动画偏好；检查弹层的主题、层级、手机溢出及焦点返回。

### 2.3 交互约束

- 聊天输入保留 Enter 发送、Shift+Enter 换行、中文输入法确认不发送；组件更新、断线和头像更新不清除草稿。原有 SSE、停止回复、历史分页和滚动跟随逻辑继续使用。
- 浏览器 `window.confirm` 改为组件确认框时，继续展示删除/重置的目标与影响。确认后仍使用原有实例代次、版本和幂等请求身份；取消不发请求，进行中的操作禁止重复提交。
- 头像选择保持手动保存，关闭组件的默认自动上传。通过现有 browser-client 发送原来的二进制 PUT 请求，沿用认证、大小/格式校验、预览释放、恢复默认和跨端更新行为。
- 表单约束继续维护在 contracts；Naive UI 负责输入和错误呈现，不另建重复的业务校验规则。重要错误使用持续可见的页面提示，短暂消息只承载适当的操作反馈。
- 记忆浏览继续执行范围、来源与生命周期校验；筛选变更重置对应游标，日期转换保持现有语义。图谱节点上限、逐层展开和键盘文本关系保留。

本轮不调整数据库结构、HTTP/SSE 协议、模型行为或服务端权限，不需要执行数据库迁移；F11 和 PM2 部署不并入本轮。

## 4. 验证安排

- 使用 Node 22：按实际改动运行格式、lint、类型检查和两个前端的生产构建。
- 复用已确认的浏览器操作边界与现有 Playwright 流程：登录、分端、个人设置、伴侣、头像、聊天、记忆、检索来源和生命周期。组件替换后按用户可见的角色/标签操作，不依赖 Naive UI 私有 DOM 结构。
- 为易回归行为补充必要的用户流程检查：中文输入法确认、确认框取消/重复点击、日期筛选与清空、头像选择但未保存。现有浏览器原生 dialog 监听改为操作实际的 Naive UI 对话框，保留原来的业务断言。
- 查看桌面和手机截图；检查至少 320px 窄屏、软键盘影响、弹层、长文本、表格溢出、聊天区滚动及星空可见性。
- 记录引入前后两个应用的构建资源大小，核对按需导入与图谱延迟加载。通过生产服务验证 CSS 动态注入、弹层和字体遵守现有 CSP；不为了组件接入放宽安全配置。
- 本轮 UI 替换不要求重跑全部后端领域测试；若实现中确实修改了公共契约或请求行为，单独评估并补跑受影响检查。
