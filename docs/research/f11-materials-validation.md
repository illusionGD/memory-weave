# F11：解析依赖与公开网页实测

验证日期：2026-11-15。对应 F11 方案 T01（历史提交 `127548d`）。这份记录保留首轮验证发现的覆盖差距。当前产品行为见 [F11 材料阅读](../features/f11-materials.md)。

## 结论与需要决定的事项

本地文档解析路线可继续：中文长文、逐页 PDF、长图分区在 Node 22.20.0 和 22.23.4 均通过实验。推荐保留 Node/Nest 部署，在可终止的解析进程中使用 Readability/jsdom、PDF.js 和 sharp。

**主要网站的正文覆盖尚未得到验证。** 普通网页成功；两份 B站视频样本取得标题、封面，但没有简介；两篇知乎文章返回验证页；公众号在本次环境的出站代理层被拒绝。公众号结果不能推断为它在用户服务器上也不可访问。这些是少量公开样本的结果，不是全站成功率。

F11 方案第 10 节约定：“T01 若显示首选路径无法覆盖主要材料，先把实际样本结果及替代方案交用户评审，不在实现中静默扩大依赖或缩小功能。”当前无法确认常用的知乎、公众号正文读取，因此先报告，T01 暂不勾选完成。

建议用户选择以下交付要求之一：

| 选择                                           | 首版如何交付                                                                                                                    | 代价与限制                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **建议：保留直接读取路线，接受明确的受限状态** | 继续实现已确认的上传、阅读、记忆和两端界面；公开链接尽力读取，失败可上传文章/截图或粘贴正文；部署后用同一探测脚本验证实际服务器 | 无新增浏览器服务或订阅；不能保证知乎、公众号直接阅读成功                        |
| 把提高知乎、公众号读取覆盖作为交付前置条件     | 先在目标部署网络和实际常用文章上验证；仍失败时，另评审浏览器读取或第三方抓取服务，再继续依赖该选择的实现                        | 需要额外验证及部署/费用决策；浏览器或第三方服务也不保证跨过登录、验证或付费限制 |

第一种沿用原方案的访问失败替代入口；此处需确认的是，实测覆盖差距是否仍符合用户对首版的预期。没有接入新服务、导入网站 Cookie 或尝试绕过验证。

## 候选依赖与部署影响

以下版本安装于独立实验目录，**尚未改应用依赖和 pnpm lockfile**。

| 依赖                   | 已验证版本 | Node engines / 结论                                                                                                         |
| ---------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| `@mozilla/readability` | `0.6.0`    | `>=14`；提取普通文章，不能单靠它识别网站主体                                                                                |
| `jsdom`                | `29.1.1`   | `^20.19.0 \|\| ^22.13.0 \|\| >=24.0.0`，满足项目最低版本；最新版 `31.0.1` 要求 `^22.22.2 \|\| ^24.15.0 \|\| >=26.0.0`，不选 |
| `pdfjs-dist`           | `6.5.438`  | `>=22.13.0 \|\| >=24`，满足项目最低版本；中文 CID 字体样本需要随包的 CMap 资源                                              |
| `sharp`                | `0.35.5`   | `>=20.9.0`；复验长图裁剪、EXIF 旋转通过，接入应用前还需回归头像流程                                                         |

依赖元数据来自 [Readability](https://registry.npmjs.org/@mozilla%2freadability)、[jsdom](https://registry.npmjs.org/jsdom)、[PDF.js](https://registry.npmjs.org/pdfjs-dist)、[sharp](https://registry.npmjs.org/sharp) 的 npm 发布记录，查询日期同上。

最初使用仓库现有 `sharp@0.34.5` 完成实验后，隔离依赖审计返回 sharp 底层组件的已知公告：[libvips](https://github.com/advisories/GHSA-f88m-g3jw-g9cj)、[libheif](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)、[librsvg](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)。因此将 F11 候选改为 `0.35.5` 并复验；隔离目录再次执行 `npm audit --omit=dev` 返回 0 项公告。此结果只覆盖实验依赖，不代表全仓库安全审计或证明不存在漏洞。

PDF.js 安装带入可选原生依赖 `@napi-rs/canvas`。本次使用其 Linux 预编译包，没有现场编译，也没有新增常驻服务；没有验证去掉该依赖的部署，不宣称 PDF.js 完全没有原生依赖。正式打包时须保留 CMap/标准字体资源并验证 Windows 和生产包路径。PDF.js 6 的释放操作在 `PDFDocumentLoadingTask.destroy()`，不能沿用旧示例中的 `pdf.destroy()`。

## 可重复的本地解析实验

实验代码：[f11-parsers.mjs](../../scripts/probes/f11-parsers.mjs)。PDF 是本项目生成的合成材料：[f11-text.pdf](../../scripts/probes/fixtures/f11-text.pdf)，不包含真实用户数据：前 12 页中文文字，第 8 页额外有“新的收件地址是星河路八号。”，第 13 页只有圆形图案。其他长文和图像在内存生成。

| 样本          | 实际结果                                                                                            | 没有证明的能力                                         |
| ------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| TXT/Markdown  | 68,000 字符 UTF-8 原文往返一致；BOM 正确处理；非法 UTF-8 拒绝                                       | GBK 自动识别、任意编码无损修复                         |
| 中文长文 HTML | 提取 2,000 段、336,899 字符；尾段保留，导航排除                                                     | 所有复杂网页/公式/表格都能还原                         |
| 中文 PDF      | 13 页中 12 页提取到文字，共 7,588 字符；第 8 页地址准确定位，第 13 页没有文字层                     | 扫描 OCR、图表理解、复杂多栏排版、100 页上限的容量保证 |
| 长图          | 1,200 × 18,000 原图分区处理，顶部/底部得到不同的 800 × 1,200 输出；EXIF 方向 6 归一化后宽高符合预期 | 模型是否读懂小字；色块样本仅验证几何处理和资源兼容性   |

所有断言在两个 Node 版本上实际执行；JPEG、PNG、WebP 编解码的格式和尺寸断言也通过，真实模型语义验收留在 F11 集成阶段。最终脚本的单次运行数据如下：

| Node    | 长文提取 | PDF 逐页提取 | 图像处理 | 整个进程峰值 RSS |
| ------- | -------- | ------------ | -------- | ---------------- |
| 22.20.0 | 994 ms   | 368 ms       | 311 ms   | 274 MiB          |
| 22.23.4 | 1,384 ms | 783 ms       | 475 ms   | 282 MiB          |

RSS 包含依赖加载与样本处理；上述是共享环境的一次进程观测，执行时还有静态检查运行，不能据此比较两个 Node 版本的性能，也不是生产峰值或吞吐基准。继续采用方案中的默认解析并发 1 和可终止的独立进程。

在项目根目录可用以下方式重跑；将实验目录放在项目以外，不改变 pnpm 工作区。需要 npm 可访问 registry。两个版本分别运行同一脚本即可对比输出。

```bash
npm install --prefix /tmp/mw-f11-probe --save-exact --ignore-scripts --no-audit --no-fund @mozilla/readability@0.6.0 jsdom@29.1.1 pdfjs-dist@6.5.438 sharp@0.35.5
node scripts/probes/f11-parsers.mjs /tmp/mw-f11-probe
```

Windows 可把 `/tmp/mw-f11-probe` 换成 `D:\temp\mw-f11-probe`；该平台尚未实测。安装默认保留 optional dependencies；`--ignore-scripts` 在本次 Linux 预编译包环境可用，其他平台如缺少二进制需先定位依赖安装问题。

## 公开网页样本

使用环境既有代理、正常 TLS 校验和不含登录信息的请求。脚本只请求固定 HTTPS 样本，不执行页面脚本、不跟随跳转、不获取视频。请求超时 15 秒、响应限制 5 MiB；输出状态和范围，临时正文随后删除。

复测命令（需安装 `curl`，Windows 调用实际 `curl.exe` 程序，不使用 PowerShell 别名）：

```bash
node scripts/probes/f11-links.mjs
```

[探测脚本](../../scripts/probes/f11-links.mjs) 是诊断工具，不是未来的生产抓取器。它的固定地址验证不能替代生产接收任意用户链接时的 DNS/每跳校验、连接地址绑定、权限和配图预算。

| 样本                                                            | 实际响应与取得范围                                                  | 产品处理结论                                           |
| --------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------ |
| [Node.js 发布文章](https://nodejs.org/en/blog/release/v22.23.0) | HTTP 200，约 297 KB HTML；Readability 提取到标题和约 9,370 字符正文 | 普通文章路线可行，但本样本不是中文平台覆盖证明         |
| [B站样本一](https://www.bilibili.com/video/BV17SzeBsEix/)       | HTTP 200；实际页面状态含标题和封面引用，简介为空                    | 标明仅页面信息，不把标题/封面当作视频理解              |
| [B站样本二](https://www.bilibili.com/video/BV1EmzeBdEJu/)       | 同上；两份样本封面另行请求均为 HTTP 200 JPEG，约 134/142 KB         | 封面可独立进入图像读取，依然不能证明看过视频           |
| [知乎文章一](https://zhuanlan.zhihu.com/p/656646499)            | HTTP 403，650 字节验证页，包含 `zh-zse-ck`；没有文章正文            | 返回访问受限，不把验证提示当作文章                     |
| [知乎文章二](https://zhuanlan.zhihu.com/p/20734615)             | 同上                                                                | 该环境下两个样本均失败，不推断为所有知乎文章永远不可读 |
| [公众号样本](https://mp.weixin.qq.com/s/slGMhoPhAQgkRE58GZBnvQ) | HTTPS CONNECT 在当前代理层返回 403，未取得源站 HTTP 响应或正文      | 原因记为当前网络不可达；源站是否开放仍待目标部署验证   |

附加发现：直接对上述 B站 HTML 运行 Readability，返回的是约 1,866 字符合集目录，不能当成视频简介。B站需要针对页面已取得的结构化信息提取，保留空简介状态。知乎验证页甚至也能被 Readability 提取为 35 字符文字，因此“解析结果非空”不能作为正文成功条件。

网页结果会随文章、站点和网络变化。搜索引擎能展示文章摘要，不代表服务端 HTTP 能取得正文；本记录没有用搜索结果代替抓取验证。公众号样本来自公开高校页面引用，但本轮未验证正文的当前有效性。
